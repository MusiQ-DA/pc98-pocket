# P0 手順4: G-RAM の SDRAM 配置と BRAM キャッシュ層(2026-09-07)

`sdram_mp` が帯域ゲートを通った(`docs/P0_SDRAM_DESIGN.md`)ことを前提に、
G-RAM を SDRAM に置くための **データ配置** と **前段キャッシュ** を決める。

---

## 1. 結論

| 決定 | 内容 |
|---|---|
| **K-1** | **4プレーンを「ワード単位でインターリーブ」して SDRAM に置く。**プレーンごとに 32KB 離して置いてはいけない |
| **K-2** | 表示フェッチは **ラインバッファ**(ダブルバッファ、1 M10K)で受ける |
| **K-3** | CPU/EGC は **ダイレクトマップのライトバックキャッシュ**(32語ライン、128ライン、約8 M10K)で受ける |
| **K-4** | TVRAM は **BRAM のまま**(SDRAM に出さない)。小さく、かつ表示中ずっと読まれる |
| **K-5** | 合計 **約10 M10K**。`P0_MEMORY.md` の見積り 20 に対し半分 |

## 2. K-1 がこの設計の要

PC-98 の 16色グラフィックは B/R/G/E の4プレーン構成で、**CPU も EGC も
「同じオフセットの4プレーンを同時に」触る**。EGC のラスタオペレーションは
16ビット単位で4プレーンを読み、合成し、書き戻す。

### 素直にプレーンごとに置くと破綻する

np2 のアドレスマップ(`VRAM_B=0xA8000` / `VRAM_R=0xB0000` /
`VRAM_G=0xB8000` / `VRAM_E=0xE0000`)をそのまま SDRAM に写すと、
プレーン間が **32KB 離れる**。すると:

- **CPU/EGC の1操作 = 32KB ストライドの4アクセス = 4つの別ロウ**
- ロウが違えば毎回 ACTIVATE + PRECHARGE。`sdram_mp` の
  1トランザクション約8サイクルのオーバーヘッドを **1語ごとに払う**
- 効率は 1/(1+8) ≒ 11%。**帯域が一桁落ちる**

### ワードインターリーブなら両方の要求が同時に満たされる

SDRAM ワードアドレスを次のように定義する:

```
sdram_word_addr = GRAM_BASE + ((page * 16000) + offset) * 4 + plane
      page   : 0..1          (VRAM0 / VRAM1)
      offset : 0..15999      (640*400/16 = 16,000 ワード/プレーン)
      plane  : 0..3          (B, R, G, E)
```

- **CPU/EGC の1操作** → **連続する4ワード**。同一ロウ内の1バースト
- **表示フェッチ** → offset を増やすだけで4プレーンが順に出てくる。**完全にシーケンシャル**
- 容量: 1ページ 16,000×4 = 64,000 ワード = 128,000 B。2ページで **256,000 B** ✓
  (`P0_MEMORY.md` §4 の実測値と一致)

**ゲストから見えるアドレス(A8000 等)→ この配置への変換は機械層で行う。**
ゲストのメモリマップは一切変えない。

## 3. K-2 表示ラインバッファ

- 1走査線 = 640 px ÷ 16 px/word = **40 ワード/プレーン**
- 4プレーンがインターリーブされているので **160 連続ワード/走査線**
- `sdram_mp` の `BURST_MAX`=32 とカラム境界(512語)に収めるため
  **32語 × 5 バースト**に分割して取る
- **ダブルバッファ**(走査線 N を表示しながら N+1 を先読み)

BRAM: 160 × 2 = 320 ワード × 16 bit = 5,120 bit → **1 M10K**

帯域: 160 語 × 400 行 × 60 Hz × 2 B = **7.7 MB/s**
(`P0_MEMORY.md` の見積りと一致。実測 53.3 MB/s の display ポートに対し余裕十分)

## 4. K-3 CPU/EGC キャッシュ

- **ダイレクトマップ / ライトバック / 32ワードライン**
  - 1ライン = 32語 = 8 オフセット × 4 プレーン
  - EGC の水平ラスタ走査は連続オフセットを舐めるので、**8オフセットぶんが1ラインに乗る**
- **128 ライン** = 4,096 語

BRAM: 4,096 × 16 bit = 65,536 bit → **7 M10K**、タグ(128×約12bit)で **+1** → **計8**

ライトバックにする理由: EGC は read-modify-write を繰り返すので、
ライトスルーだと書き込みのたびに SDRAM トランザクションが立つ。

## 5. K-4 TVRAM を SDRAM に出さない理由

TVRAM はコード+アトリビュートで **16KB(13 M10K)**。SDRAM に出すと
テキスト表示のために毎走査線フェッチが増えるうえ、CPU のテキスト書き込みが
キャッシュを汚す。**BRAM に置いたままにする。**

## 6. BRAM 収支(更新)

| 項目 | M10K |
|---|---:|
| 表示ラインバッファ(K-2) | 1 |
| CPU/EGC キャッシュ(K-3) | 8 |
| TVRAM(K-4) | 13 |
| ANK フォント + 漢字キャッシュ | 16 |
| FDC / GDC / OPNA ワーク | 15 |
| V30 / `pocket_video` / シャーシ | 36 |
| `softcpu_subsystem`(現状のまま) | 110 |
| **合計** | **199 / 308** |

→ **余裕 109 ブロック。** `P0_MEMORY.md` §6 の C 試算(約210)より更に良い。
OSD を削る必要は引き続きない。

## 7. 未検証の前提(実装時に潰すこと)

1. ~~EGC のアクセス粒度~~ ✅ **np2 ソースで確認済み(2026-09-07)**
   `mem/memegc.c` は EGC の読み書きすべてで
   `mem[ad + VRAM_B]` / `+ VRAM_R` / `+ VRAM_G` / `+ VRAM_E` を
   **同一の `ad`** に対して操作しており、値は `EGCQUAD`
   (`UINT16 w[4]` / `UINT64 q`、`io/egc.h`)として **1操作で4プレーンまとめて**扱われる。
   `lastvram` / `patreg` / `fgc` / `bgc` もすべて EGCQUAD。
   → **K-1(ワードインターリーブ)の前提は成立する。**
2. **キャッシュのライン数・サイズが EGC の実アクセスパターンに合っているか。**
   128ライン ダイレクトマップは、EGC が離れた2領域を交互に舐めるとスラッシングする。
   → 実装後に `tb_sdram_load` を EGC 相当のトレースで駆動して測る
3. **ページフリップ時のキャッシュ無効化。**
   描画ページが切り替わったらキャッシュをフラッシュする必要がある。
   フリップが毎フレーム起きるなら、フラッシュのコストが効く可能性がある
