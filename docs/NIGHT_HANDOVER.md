# ハンドオバー改訂版 (2026-09-12 昼) — F3AD9/高ベクタの謎、全て解明

## 本日の確定事項

### 1. ブート契約は完成(両モードで実証)

```
電源オン → ITF (メモリカウント~40s) → OUT 0F0h CPUリセット
        → BIOS POST:
            FD80:0130-0x15F: 8251初期化 {02,40,5E,3A,32,16} → 0x43
            FD80:0164-0x177: キーボードテスト (0x43 bit1ポール→0x41読→0x60比較)
                実機: ~40msポール窓 vs キーボード応答 ~30ms → 微妙
                np2: 常にタイムアウト(テスト失敗) ← これが正規経路
            → [0x500].bit7 = 0 → FDB1E: IVT[1E]={E800:0000} インストール!
        → FD80:0A05: int 1E → E800:0000 BASICエントリ ✓
```

**ベンチ実装済み**: ACK遅延80ms(3.4M チップセットティック)—
ブートテストはタイムアウト(bit7=0 ✓ インストール ✓)、
以降のポールはACKを受ける(キーボード初期化 ✓)。

### 2. SS=0xF202 は赤リングだった

nuV30はdecap検証済み実シリコン。エントリスタブの 0x66 プレフィックス
命令(`66 18 77 d5`)は実機も FFDA ショートカットに入り、フラグ語
(0xF202 = 定番の8086フラグ画像)を一時的にSSへロードする。その直後
F000:0038 で `mov ss,0x60; mov sp,0xF000` が正しく復帰(実測)。

### 3. 本当の脱線 = 高ベクタ未インストール

```
F3AD9 (文字列コピーloop、ES:DIがROMを指いたまま) → EBAE7: int 0xC2
→ IVT[0xC2] = RAMテストのゴミ → 1B5D9 (空RAM) → 転落
```

**高ベクタのインストーラは BASIC 自身:**

```
E800:8E18: IVT[0x18] を [0x15F1] へ退避
E800:8E28: for di=0x80..0x3FE: IVT[n] = {E800:11C0}   ← 全高ベクタ
E800:8E3A: IVT[0xC4] = {E800:118C}
```

E800:11C0 = 文字列移動ディスパッチャ(深部initトレースの F11B9/F0E2B)。
**我々のマシンは FFDA ショートカット([0x1866]=0 が原因)で 8E18 の
呼び出し元まで到達しない。**

### 4. 残る問題: [0x1866]=0 → FFDA ショートカット

- 正規パス: E800:0009 `jmp FFE1` → FFE1 → FE95 (`call FCA4` — [0x6EA]=SI!)
  → FEB8 ディスパッチ → 各ハンドラ → FE24ブロック
  ([0x1862]/[0x1866]/[0x186C] = BX=[0x1406] を設定)
- 我々のマシン: **FE24ブロックが走らない** — 呼び出し条件
  `[0x6A4] < [0x6A6]`(コマンドキュー非空)が不成立
- [0x1406](ワーク上限)はROM中に直接の書き込み手なし(レジスタ経由のみ)
- コマンドキュー [0x6A4]/[0x6A6] も同様 — 実機は何が这些を設定する?
