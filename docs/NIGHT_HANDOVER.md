# 今夜のハンドオバー (2026-09-12 早朝)

## 状態: SS=0xF202 の完全な因果鎖が判明。残るはキーボード8251テスト1件。

## 確定した因果鎖 (全て実測)

```
BIOS POST
  └ FD80:0A02: mov ss,0x30 / mov sp,0xFE    ← POSTスタック初期化
  └ FD80:61DA: mov di,0x400 / rep stosw     ← ワークエリア [0x400-0x5FF] クリア
  └ FD80:61E3-61EC: 各種call (デバイス初期化、キーボードテスト含む)
  └ FD80:61F2: test [0x500],0x80            ← キーボードテスト成功フラグ!
      └ 我々のマシン: bit7=0 (テスト失敗) → FD80:61FA: call 625E
          └ 第2拡張ROMスキャン (FE2A0ループ)  ← [0030:00F8]=0x0F スクラッチ残置
  └ FD80:6205: int 0x1E
      └ push flags=0xF202 → [0xFC-0xFD] (8086フラグの定番値!)
      └ push CS=FD80     → [0xFA-0xFB]
      └ push IP          → [0xF8-0xF9] を上書き
  └ E800:0000 BASIC入口: push es (ES=0x0A07 — 既に異常値)
  └ エントリスタブのポップ連鎖 → F000:7D80: pop ss ← [0x3FC]=0xF202
  └ SS=0xF202 (ROM領域!) → スタック操作が全てROMに吸われる
  └ F3AD5: lcall [DS:0x15C6] がゴミポインタを読む → 脱線
```

## 実機との違い = ビット1つ

**[0x500].bit7 = キーボードテスト成功フラグ。** 実機(キーボードあり)は
これが立つ → 第2スキャンをスキップ → スタックがROM設計通りの深さ →
BASICのポップ連鎖が正しい値を得る。我々の8251モデルはBIOSの
テストに失敗し続けている(0x31=0x11 の旧設定でも同じく失敗)。

## 走行中の実験

`vfix` コンテナ: KBD RD/WR (0x41/0x43/0x32) + [0x500] 変化トレース。
ブート判断 (~29.7s sim) でキーボードテストのI/O列が取れる。
**失敗の交換手順が分かったら 8251 モデルを直す → bit7=1 → 再実行。**

## 今夜の他の成果

1. **メモリスイッチ契約解明** (np2kai pccore_reset 実装より):
   - 実機はA3FE2+4iに {48 05 04 08 01 00 00 6E} が「事前書き込み」されている
   - FEA=4 が 640KB 値。ROM自身のライターは最大2 (512KB級) しか書けない
   - DIP 0x31 は 0xE3 (bit4=クリア=ROMにスイッチを初期化させない)
   - **ITFのVRAMテストは 0x3FDF で止まる** = A3FE0-A3FFF は書き込み保護領域
   - ベンチ実装済み: tvram の 0xFF0-0xFFF attr 書き込みドロップ + プリシード
   - 実測: BOOTDEC で FE2=48 FE6=05 FEA=04 が生存確認 ✓

2. **np2kai ヘッドレスハーネス** (docs/NP2KAI_HARNESS.md):
   - libretroコアをビルドして /tmp/np2run でドライバー駆動
   - 設定契約の抽出に成功 (MEMswtch/DIPswtch)
   - 注意: np2のi386cコアは ia32reset() で CPU_TYPE をゼロにする
     (dipsw[2]&0x80 の V30 指定は効かない)。純正ROMブートは
     np2 の本来の検証対象外 (biosfunc シミュレーションが正規経路)

3. **F000:7DAE/7DB2 共有プロローグ/エピローグ**、F8B60 スクリーンクリアの
   `push bp; ret` イディオム、INT 0x80 ディスパッチ (IVT[0x80]=F758:15AC)、
   E800:FCB9 の `[06EA]=SI` 書き込み — ROMの構造判明。
