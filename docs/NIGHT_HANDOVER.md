## 残る問題(1つ): ワークエリア契約

エントリスタブのディスパッチ(E800:40A8=コマンドプロセッサ)からの
retチェーンが、int 1Eのスタックフレームを消費する:
- retがESをIPとして使う(ES=スキャン残骸のA000/DF00)
- その後のpop ssルーチン(F000:7D80)がフラグ語(f202)をSSへ

**実機ではnp2の`bios_reinitbyswitch`相当の初期化が、これらの値を
正しく設定する。** 具体的には:
- [0x6EA] = ブートコマンド文字列ポインタ(FCA4がSIから設定=動作済み)
- ES = BASICワークセグメント(0x0600?)
- [0x6A4]/[0x6A6] = コマンドキュー(ディスクなし=空で正しい)
- [0x1406] = ワーク上限

**測定済み: FD80 BIOS内の誰もこれらを設定しない**(RAMテストのみ)。
np2はシミュレーションで直接設定。実機は…IPL/キーボードID/拡張ROM
のいずれかが設定するはず。

## 重要な発見(参考)

- **nuV30のバグ**: 0x66プレフィックス後のショートジャンプが
  誤ターゲット(キュー/EU残渣)。実シリコン検証の3.1Mケースに
  この組み合わせが無かったと思われる。`bios.hex[1]:=0x90`で回避
- **SS=0xF202は実機でも発生する値**(int 1Eのフラグ)だが、
  正規経路ではpop ssルーチンに到達前に別のSSがプッシュされる
- **FF8CCループは `mov cx,0x4000; loop $` = 単なるディレイ** —
  マシンは止まっておらず、初期化が非常に遅いだけ
