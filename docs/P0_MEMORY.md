# P0: メモリアーキテクチャ決定(2026-09-07)

GOAL.md R1(G-RAM をどこに置くか)への回答。**P3(GDC)着手前の必須決定。**

---

## 1. 結論

| 決定 | 内容 |
|---|---|
| **D-1** | **現行 `KFSDRAM` のままでは G-RAM を SDRAM に置けない。** ただし制約は**コントローラ**であってデバイスではない(§3) |
| **D-2** | **2ページ(256KB)を BRAM に載せることは不可能。**容量が物理的に足りない(§4) |
| **D-3** | **np2 の実装上、PC-98 の 2ページ VRAM は実在し使われている**(§5)。1ページ構成は恒久的な互換性上限になる |
| **D-4** | → **選択肢は「1ページで妥協」か「SDRAM コントローラを作り直す」の二択**(§6)。**ユーザー判断待ち** |
| **D-5** | いずれの場合も **OSD フレームバッファ縮小(+32 M10K)は先行実施する**。損にならない |
| **D-6** | 漢字フォント・OPNA の ADPCM/リズムは **SDRAM 常駐**(BRAM は ANK とキャッシュのみ) |

## 2. ボトルネックの正体

「M10K が足りない」の内訳を B0 の fit レポートで実測した結果、
**逼迫の主因は PC-98 機械層ではなく、シャーシ側の設定だった。**

| 使用者 | M10K | 内訳 |
|---|---:|---|
| `softcpu_subsystem` | **110** | **OSD フレームバッファ 64** / firmware ROM 32 / 作業RAM 8 / その他 6 |
| `CHIPSET`(PC/AT 機械層) | 47 | IDE dpram 16 / OPL2 9 / その他 22 |
| `i8088` | 16 | |
| `pocket_video` | 10 | |
| その他 | 10 | |
| **合計** | **193 / 308** | |

- **OSD フレームバッファ = 640×200 @ 4bpp = 62.5KB で 64 ブロック。**
  設計全体で単一最大の BRAM 消費者であり、**PC/AT 機械層 47 ブロックより大きい。**
- **firmware ROM は 24KB 確保して 17.6KB しか使っていない**(4,407/6,144 ワード)。

→ **削減余地は機械層ではなくここにある。**

## 3. SDRAM の実力(D-1 の根拠)

### 制約はコントローラであって、デバイスではない

**デバイス**(`apf_top.v` のピン定義)は標準的な SDRAM:

| 項目 | 値 |
|---|---|
| データ幅 | 16 bit (`dram_dq[15:0]`) |
| バンク | **4** (`dram_ba[1:0]`) |
| アドレス | 13 row (`dram_a[12:0]`) / 9 col |
| 容量 | 32 MB |

**バンクが4つある = バンクインターリーブが可能。**

**コントローラ**(`KFSDRAM.sv`)はこれを一切活かしていない:

| 項目 | 値 |
|---|---|
| クロック | 42.95 MHz(`SDRAM_CLK = clk_chipset`) |
| CAS レイテンシ | 2 |
| ポート数 | **1(CPU メインRAM と共有)** |
| 構造 | **アクセスごとに PRECHARGE**(`IDLE→READ/WRITE→PRECHARGE_WAIT→PRECHARGE`)。**バンクインターリーブなし、オープンロウなし、パイプラインなし** |

理論ピーク 85.9 MB/s に対し、ランダムアクセスは毎回プリチャージが入るため
**実効は一桁 MB/s 台**。一方 G-RAM を置いた場合の要求は:

| 用途 | 帯域 | 性質 |
|---|---:|---|
| 表示リフレッシュ(640×400×4プレーン @60Hz) | 7.7 MB/s | シーケンシャル |
| EGC 全画面 read-modify-write @60Hz | 約 15 MB/s | **ランダム** |
| CPU メインRAM アクセス | 常時 | **同じ1ポートを奪い合う** |

→ **現行コントローラのままでは D5(EGC 正速)と両立しない。**

### 作り直せば改善は見込めるが、先例は「SDRAM に置く」ではない

バーストアクセス + バンクインターリーブ + クロック引き上げにすれば
同じデバイスで数倍の改善が見込める。移植元にできる GPL 実装も存在する
(`X68000_MiSTer` の `rtl/memory/SDRAMC.vhd`: **80MHz / 16bit / バースト**、
`bgnaddr`/`endaddr`/`bwidth` でロウ内バースト転送する設計)。
**`pcxt-base` は GPLv3 なので、MiSTer 系 GPL コードの移植に支障はない。**

> **⚠ 訂正(2026-09-07)**: 当初「X68000_MiSTer は VRAM を SDRAM で運用している」
> と書いたが、**これは誤り**。実際は `rtl/memory/gvram_bram.vhd` が
> `ram_block_type => "M10K"` で **2チップ × 65,536 × 16bit = 256KB を BRAM に確保**
> しており、**GVRAM は BRAM にある**。
> **つまり「VRAM を SDRAM に置く」ことの先例にはならない。**
> むしろ、80MHz バースト SDRAM コントローラを持っている作者が、
> それでも VRAM は BRAM に置く選択をした、という事実である。
> (ただし DE10-Nano の 5CSEBA6 は **M10K 553 ブロック**あり、
>  256KB = 205 ブロックでも 37% で済む。Pocket の 308 ブロックでは 67%。
>  BRAM が潤沢だったから選べた、という可能性は高い)

### X68000_MiSTer の実際のメモリ構成(参考になるのはこちら)

| 対象 | 置き場所 | 前段 |
|---|---|---|
| メインメモリ | **SDRAM**(`SDRAMC.vhd` 80MHz バースト) | **キャッシュ**(`cachecont.vhd`) |
| GVRAM | **BRAM**(`gvram_bram.vhd`) | **表示用ラインキャッシュ**(`CACHEMEMWN` ×4プレーン) |

→ **重い VRAM アクセスを SDRAM に生で当てる設計にはなっていない。**
SDRAM を使うなら **BRAM キャッシュを前段に置くのが前提**、という示唆。

## 4. 容量収支(D-2 の根拠)

M10K 総数 **308**(= 3,153,920 bit = 385 KB)。

### PC-98 の VRAM 実サイズ(np2 ソースで確定)

`i386c/cpumem.h`(NP2kai master、2026-09-07 取得):

```
#define VRAM_STEP  0x100000
#define VRAM_B     0x0a8000    #define VRAM_R  0x0b0000
#define VRAM_G     0x0b8000    #define VRAM_E  0x0e0000
#define VRAMADDRMASKEX(a)  ((a) & (VRAM_STEP | 0x7fff))
#define VRAM0_B  VRAM_B                 ...
#define VRAM1_B  (VRAM_STEP + VRAM_B)   ...
```

- プレーンごとのマスクは `0x7fff` = **32 KB**
- プレーンは **B / R / G / E の4枚** → **1ページ = 128 KB**
- **`VRAM0_*` と `VRAM1_*` の2バンクが定義されている → 2ページ = 256 KB**

### 収支

| 項目 | 1ページ | 2ページ |
|---|---:|---:|
| G-RAM(実装上の丸めを含む) | 100 | **208** |
| TVRAM(コード+アトリビュート 16KB) | 13 | 13 |
| ANK フォント + 漢字キャッシュ | 16 | 16 |
| FDC セクタバッファ / GDC FIFO ほか | 10 | 10 |
| OPNA 演算ワーク(本体は SDRAM) | 5 | 5 |
| V30 | 16 | 16 |
| `pocket_video` | 10 | 10 |
| シャーシ その他 | 10 | 10 |
| `softcpu_subsystem`(**最大限削減後**: OSD 16 + ROM 26 + 作業 14) | 56 | 56 |
| **合計** | **236 / 308** ✅ | **344 / 308** ❌ |

- **1ページ: 収まる**(現状の softcpu 110 のままでも 290/308 で収まる)
- **2ページ: OSD を極限まで削っても 36 ブロック超過。**

**G-RAM 2ページ(256KB)だけでチップ全 BRAM の 66% を占める。**
BRAM に載せる案は算術的に成立しない。**これは確定。**

## 5. ページ切替は実際に使われている(D-3 の根拠)

np2 のコードは表示側・描画側の両方でページを切り替えている:

| 箇所 | 内容 |
|---|---|
| `vram/maketgrp.c:137,395` | `ppage = (plane) ? VRAM_STEP : 0;` — **表示ページ選択** |
| `io/gdc_sub.c:634` | `ptr += VRAM_STEP;` — **GDC の描画先切替** |
| `io/gdc_pset.c:126` | `base += VRAM_STEP;` — ピクセル描画先切替 |
| `vram/makegrph.c:217,325` | 合成時の他ページ参照 |

→ **2ページは飾りではなく、エミュレータが実装している実機能。**
1ページ構成にすると、ページフリップするタイトルは
**クラッシュではなく「描画途中が見える / ちらつく」形で破綻する。**

※ ただし **「検収タイトルがページフリップを使うか」は未確認**。
   PC-98 のタイトルには静止画中心の ADV/RPG も多く、
   1ページで問題ないものも相当数あると見込まれる(定量的な根拠はない)。

## 6. 選択肢

| 案 | 内容 | 容量 | 互換性 | コスト |
|---|---|---|---|---|
| **A** | 1ページのみ、BRAM | ✅ 236/308 | ❌ ページフリップ不可(恒久的な上限) | 小 |
| **B** | 2ページ、BRAM(素直に) | ❌ 344/308 | — | 不可能 |
| **E** | 2ページ BRAM + **OSD全廃・キャッシュ極小化** | △ ぎりぎり届かない〜同等 | ✅ | 中。**D6(仮想キーボード)を失う** |
| **C** | **G-RAM を SDRAM へ + BRAM キャッシュ前段 + コントローラ作り直し** | ✅ 約210/308 | ✅ 2ページ可 | **大。本プロジェクト最大のインフラ作業** |

### E の試算(2ページ BRAM を無理に通す場合)

| 項目 | M10K |
|---|---:|
| G-RAM 2ページ | 205 |
| TVRAM | 13 |
| ANK フォントのみ(漢字キャッシュ廃止) | 5 |
| FDC / GDC 最小 | 7 |
| V30 | 16 |
| `pocket_video` | 10 |
| シャーシ その他 | 10 |
| softcpu(**OSD全廃**: ROM 26 + 作業 14) | 40 |
| **合計** | **306 / 308** |

→ **数字上は通るが余裕ゼロ。しかも OSD(仮想キーボード)を失う。**
PC-98 はキーボード必須のソフトが多く、**D6(実用的に遊べる)と衝突する。**

### C の試算

| 項目 | M10K |
|---|---:|
| G-RAM | **0**(SDRAM) |
| 表示ラインキャッシュ + EGC ワーキングセット + CPU アクセスキャッシュ | 20 |
| TVRAM / 漢字キャッシュ / FDC / GDC / OPNA | 44 |
| V30 / `pocket_video` / シャーシ | 36 |
| softcpu(現状のまま) | 110 |
| **合計** | **約 210 / 308** |

→ **余裕 約100ブロック。**R2(漢字フォント)R3(OPNA ADPCM)の圧力も同時に下がる。

**採用: C(2026-09-07 ユーザー決定)。**
ただし **先例がない新規設計**であることを明記しておく。
X68000_MiSTer の作者は 80MHz バーストコントローラを持ちながら
VRAM は BRAM に置いた。C はそこから一歩踏み出す判断である。

## 7. 実装順序

**C の成否は帯域の実測で決まる。設計を広げる前に数字を取る。**

1. ~~OSD FB 縮小~~ — **C では不要**。C は BRAM を約100ブロック余らせるので、
   OSD を削る理由がなくなった(firmware 側の描画コードを触るリスクだけが残る)
2. **SDRAM コントローラの置換**
   - `X68000_MiSTer` の `SDRAMC.vhd`(GPL、80MHz バースト)を移植候補とする
   - マルチポート化(CPU メインRAM / G-RAM / 表示フェッチ)
3. **帯域の実測** ← **ここが分水嶺**
   - 合成して Fmax を確認、実機で実効転送レートを測る
   - 要求: 表示 7.7 MB/s(シーケンシャル)+ EGC 約 15 MB/s(ランダム)+ CPU
   - **届かなければ A へ後退する。その判断をここで行う**
4. BRAM キャッシュ設計(表示ラインバッファ / EGC ワーキングセット)
5. P1 以降へ

### 撤退ライン

**手順3で必要帯域に届かない場合、C を諦めて A(1ページ)に戻る。**
その時点で D2/D5/D6 の達成範囲をユーザーと再交渉すること。
深追いすると P1〜P7 が丸ごと止まる。
