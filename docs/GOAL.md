# プロジェクトゴール(確定版 2026-09-07)

このプロジェクトの**唯一の正**となるゴール定義。
各セッションはここを読んでから `docs/HANDOVER.md` §5 の作業リストに進むこと。

---

## 1. ゴール(「本命」)

> **Analogue Pocket 実機で、PC-98 用ソフト(ゲーム)が
> GDC グラフィックと FM 音源つきで実用速度で動く。**

「BIOS が出た」「DOS が起動した」は**通過点であってゴールではない**。
ゴールは実際のタイトルが遊べる状態。

## 2. 完了条件(Definition of Done)

すべて **Analogue Pocket 実機**で確認できること(エミュレータ・シミュレーションは不可)。

| # | 完了条件 | 判定方法 |
|---|---|---|
| D1 | FD イメージから PC-98 の MS-DOS が起動し、コマンドが打てる | DOS プロンプトでコマンド実行 |
| D2 | GDC の 640×400 16色グラフィックが正しく表示される | 実タイトルのタイトル画面が化けずに出る |
| D3 | テキスト(ANK + 漢字)が正しく表示される | DOS のメッセージと漢字が読める |
| D4 | OPNA(YM2608)で BGM が鳴る | PMD/FMP 等のドライバを使うタイトルで曲が正しく鳴る |
| D5 | EGC を使うタイトルが**正速**で動く | 実速比較でコマ落ち・速度落ちがない |
| D6 | ゲームパッドで操作でき、実用的に遊べる | 1タイトルを通しでプレイできる |
| D7 | 上記が**同一ビットストリーム**で成立する | 機能を削った別ビルドではない |

**D7 が本質的な難所**。個々の機能は単体なら入るが、全部同時に載るかは別問題(§4 参照)。

### 検収タイトル

判定を主観にしないため、**検収に使うタイトルを1本決めてから D2/D5/D6 を判定する**。
条件: V30 で動く / GDC 16色 / OPNA 対応 / EGC 使用。
※ 具体的なタイトルは未決定。ユーザーが所有するイメージから選定すること。

## 3. スコープ

**対象**: PC-9801VX 級(V30 @ 8/10MHz、640×400 16色、86音源相当)

**含む**: V30/8086 互換 CPU / 640KB + 拡張 RAM / GDC(μPD7220)×2 /
TVRAM + 漢字 ANK 表示 / EGC / uPD765 FDC(**1024B/セクタの 1.2MB 必須**) /
uPD71071 DMA / 8259 PIC ×2 / 8253 PIT + BEEP / OPNA(YM2608) + OPN(YM2203) /
ゲームパッド + Dock キーボード/マウス + 仮想キーボード

**含まない**: 80286/386/486(→ TH04/05 等の 486 必須級タイトルは対象外) /
YM2151(OPM。PC-98 に存在しない) / PC-9821 系の拡張ビデオ(256色等) /
ネットワーク・プリンタ

## 4. 容量予算(B0 の fit レポートから実測、2026-09-07)

|---|---:|---:|---:|---|
| `CHIPSET`(PC/AT 機械層一式) | 6,428 | 47 | 7 | **丸ごと置換** |
| `softcpu_subsystem`(picorv32+OSD) | 1,974 | 110 | 0 | 流用 |
| `i8088`(CPU) | 806 | 16 | 0 | 流用 → V30 化 |
| `pocket_keyboard` | 642 | 1 | 0 | 流用 |

→ **シャーシ(CHIPSET 以外)= 5,621 ALM / 146 M10K / 9 DSP**

### PC-98 機械層に使える残り

| 資源 | 残り | 参考: PC/AT 機械層の実績 |
|---|---:|---|
| ALM | **12,859 (70%)** | 6,428 |
| M10K | **162 (53%)** | 47 |
| DSP | **57 (86%)** | 7 |

**ALM は余裕がある。ボトルネックは M10K(162 ブロック ≒ 202KB)。**

参考: 撤去できる PC/AT 固有ブロック → `saa1099`×2 = 932 ALM、
`jtopl2`(OPL2)= 554 ALM + 9 M10K、`cga` = 546 ALM。合計 **約 2,030 ALM が浮く**。

## 5. 最大の技術リスク(先に潰すべき順)

### R1. G-RAM をどこに置くか → **決着済み(2026-09-07)**

**`docs/P0_MEMORY.md` で決定。SDRAM は使えず、BRAM 一択。**

理由: `KFSDRAM.sv` は **16bit / 42.95MHz / 単一ポート / アクセスごとPRECHARGE**
で、CPU メインRAM と共有。実効帯域は一桁 MB/s 台なのに対し、
EGC 全画面 RMW は約 15MB/s を要求する。**D5(EGC 正速)と両立しない。**

**残る問題は容量。** G-RAM 1ページ = 100 M10K は収まる(144/162)が、
**2ページ = 200 M10K は削減を尽くしても 28 ブロック不足で載らない。**
→ 2ページが必須と判明したら **D5 か D7 のどちらかを諦める再交渉が必要**。
P3 着手前に np2 ソースで確認すること(P0_MEMORY.md §5)。

なお **M10K 逼迫の主因は機械層ではなくシャーシ**だった:
OSD フレームバッファが単独で 64 ブロック(PC/AT 機械層 47 より大きい)、
firmware ROM が 24KB 確保で 17.6KB しか使っていない。

### R2. FONT.ROM 288KB は BRAM に入らない

実測 `FONT.ROM = 288,768 B`。M10K 全体(384KB)の 75%。
→ 漢字フォントは SDRAM 常駐 + ANK(8×16、約 4KB)のみ BRAM キャッシュ、が現実解。

### R3. OPNA のリズム音源に ROM ダンプが存在しない

`~/Documents/lodemnc/np2rom/` の実測:

| ファイル | サイズ | 正体 |
|---|---:|---|
| `BIOS.ROM` | 98,304 | PC-98 BIOS(96KB) |
| `FONT.ROM` | 288,768 | ANK + 漢字フォント |
| `ITF.ROM` | 32,768 | 初期化ファーム |
| `sound.rom` | 16,384 | **サウンドボード BIOS(16KB)** |
| `2608_*.WAV` ×6 | 計 約 82KB | **リズム音源のPCMサンプル** |

- **PORT_PLAN #8 の「sound.rom = 128KB」は誤り。実際は 16KB。**
  しかもこれは YM2608 のリズム ROM ではなく、-26/-86 ボードの BIOS ROM。
- **YM2608 内蔵リズム ROM のダンプは存在せず、np2 は WAV で代用している。**
  → 実機で D4 を満たすには、この WAV を ADPCM-A データに変換して
  アセットとして配る(または SDRAM に展開する)設計が要る。**未設計。**

### R4. D7(全部入り単一ビットストリーム)

pcxt-base は `src/fpga/config.tcl` の `VERILOG_MACRO` で機能を出し入れする
仕組みを既に持っている(`ENABLE_CGA` / `ENABLE_OPL2` 等)。
PC-98 でも同じ仕組みを踏襲し、**開発中は機能を落として通し、最後に全部入りを通す**。
ただし **D7 は「全部入りが通ること」なので、機能を落とした版は完了条件を満たさない。**

| # | マイルストーン | 完了条件 | 対応 DoD |

| B0 | PCXT ベースが実機でロードできる | ✅ 2026-09-07 達成 | — |
| B1 | PCXT ベースが実機で DOS ブート | 実 firmware で BIOS POST → DOS | — |
| P0 | **G-RAM 配置とバス構造の決定** | ✅ 2026-09-07 決定(`docs/P0_MEMORY.md`)。残: 2ページ要否の確認 | D5 |
| P1 | PC-98 メモリマップ + BIOS フェッチ | BIOS が実行される | — |

| P3 | GDC 640×400 16色 | グラフィック画面が出る | D2 |

| P6 | EGC | 検収タイトルが正速で動く | D5 |

## 7. `/loop` で回す場合の指示文

```
/loop docs/GOAL.md のゴール達成に向けて進める。現在地と次の一手は
docs/HANDOVER.md §5 を唯一の正とする。1イテレーションで
(1) 未完タスクを1つ進める (2) 結果を HANDOVER.md に反映 (3) commit する。
実機テストが必要な段階に来たら、SD への投入まで済ませてユーザーに依頼し停止する。
CI ビルド待ちの間は待たずに次のタスクへ進む。
```

**「実機テストが必要になったら止まる」を必ず入れること。**
実機検証はユーザー担当(HANDOVER §7)なので、これを書かないとループが空回りする。
