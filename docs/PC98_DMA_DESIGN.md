# DMA — 置き換えは不要だった(調査記録、2026-09-14)

## 結論

**PC-98 の DMA は既に正しく実装されている。** `KF8237` という名前が XT 由来
なだけで、ポート写像もレジスタのずらし方も PC-98 のものになっている。
uPD71071 への「置き換え」は不要。

## そう誤解した経緯

XT 要素の棚卸しで「PC-98 の DMA は uPD71071、`KF8237` は i8237 だから
レジスタ配置が別物」と書いた。**チップ名だけを見た推論で、根拠がなかった。**

## 実際に確かめたこと

### 1. np2kai のポート写像

`io/dmac.c`: `iocore_attachsysoutex(0x0001, 0x0ce1, dmaco00, 16)` — 奇数番地
16 本。チャネルは `(port >> 2) & 3`:

| ポート | 役割 |
|---|---|
| 0x01 / 0x05 / 0x09 / 0x0D | アドレス ch0-3 |
| 0x03 / 0x07 / 0x0B / 0x0F | カウント ch0-3 |
| 0x11 | ステータス(読み) |
| 0x13 / 0x15 / 0x17 / 0x19 / 0x1B / 0x1D / 0x1F | リクエスト / 単一マスク / モード / FF クリア / マスタクリア / 全マスク解除 / マスク一括 |
| 0x21-0x2F 奇数 | バンク(ページ) |

**これは i8237 のレイアウトをポート間隔 2 倍にしたもの**であって、
uPD71071 の「拡張モード」ではない。

### 2. MAME の uPD71071(拡張モード)は別物

`src/devices/machine/am9517a.cpp` の `upd71071_device::write()`:

| offset | 役割 |
|---|---|
| 0x00 | 初期化(bit 0 = ソフトリセット) |
| 0x01 | **チャネル選択**(`data & 3`) |
| 0x02 / 0x03 | カウント 下位 / 上位 |
| 0x04 / 0x05 / 0x06 | アドレス 下位 / 中位 / 上位(24 ビット) |
| 0x08 / 0x09 | デバイス制御 下位 / 上位 |
| 0x0A | モード制御 |
| 0x0E / 0x0F | リクエスト / マスク |

**チャネルをポートではなくレジスタで選ぶ。** np2kai とも PC-98 とも一致しない。

uPD71071 には **8237A 互換モードと拡張モードの二つ**があり、
**PC-98 は互換モードで使っている。** だから np2kai の写像が i8237 形なのは
正しく、MAME の実装と食い違うのも正しい。

### 3. このツリーの実装は既に PC-98 化されている

`Peripherals.sv:318`:

```systemverilog
assign dma_chip_select_n      = ~(pc98_io &  address[0] & ~address[7] & ~address[6]
                                           & ~address[5] & ~address[4]);   // 0x01-0x1F 奇数
assign dma_page_chip_select_n = ~(pc98_io &  address[0] & (address[7:4] == 4'h2)); // 0x21-0x2F 奇数
wire   [3:0] dma_reg_addr     = address[4:1];   // ポート間隔 2 倍を吸収
```

np2kai の写像と一致する。

## 教訓

このツリーはこの日、**根拠のない説を三度立てかけた**:

1. ROM が対になっていない(撤回、`docs/FRANKEN_ROM_LESSON.md` の 2 件目)
2. グラフィックの 4 枚目がマップから漏れている(訂正、実際はモード依存)
3. DMA が i8237 のままで置き換えが要る(この文書、実際は既に PC-98)

三度とも「チップ名や定数だけを見て、実装を確かめなかった」。
3 だけは**実装を書き始める前に**止まった — 止めたのは「Web で確認して」という
指示だった。

**チップ名は仕様ではない。** 同じ型番に複数のモードがあり、参照実装どうしが
食い違うことがある。np2kai だけでも MAME だけでも足りなかった。
