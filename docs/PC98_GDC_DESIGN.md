# GDC (µPD7220) 設計 — 表示制御を先に、描画プロセッサを後に

## なぜ今これなのか

テキストは既に出ている（ITF のメモリテストの数字が読める）。しかしそれは
`pc98_text_render` が `hcount`/`vcount` から**セル番号を直接計算している**からで、
GDC は存在しない。ポート 0x60 / 0xA0 は読み出し専用のモックが
`{0, hb, vs, 0, 0, 1, 0, 1}` を返すだけ（`Peripherals.sv:1638`）。

したがって今は次のどれもできない:

- 画面のスクロール（GDC の START アドレスと SCROLL 分割）
- カーソル（CSRW / CSRFORM）
- グラフィック画面の表示（スレーブ GDC）
- 40 桁モード、行数変更、ZOOM

「BIOS 画面が出る」ところまでは来たが、「ソフトが動く」には GDC が要る。

## 面積の制約

デバイスは 5CEBA4F23C8、18,480 ALM。直近のフィットで 17,977 (97%)。
nuV30 が 7,753 ALM を占めるのは測定済みで、サイクル精度と引き換えに受け入れた
（`scripts/measure_core.sh` で i8088 682 / Zet 2,179 / nuV30 7,753 を実測）。

回収済み: XT の RTC + 16550×2 = 761、picorv32 の除算器 = 216。**合計 977。**
空きは 503 + 977 = **1,480 ALM**。

これが設計を決める。GDC を「フル実装」すると入らない。

## スコープ

### 第1期 — 表示制御（これをやる）

| コマンド | 何のために |
|---|---|
| `RESET` (0x00) / `SYNC` (0x0E/0x0F, 8 パラメータ) | 同期パラメータ。ここを読まないと行数・桁数が固定のまま |
| `MASTER` (0x6F) / `SLAVE` (0x6E) | マスタ/スレーブの役割 |
| `START` (0x0D/0x6B) / `STOP` (0x0C/0x05) | 表示のオン・オフ。BIOS が画面を消す |
| `SCROLL` (0x70, PRAM 8 バイト) | **表示開始アドレスと分割**。4 領域の SAD/LEN。スクロールの実体 |
| `PITCH` (0x47) | 1 行あたりのワード数。40 桁モードで変わる |
| `CSRW` (0x49) / `CSRFORM` (0x4B) | カーソル位置と形状・点滅 |
| `ZOOM` (0x06) | 拡大 |
| `MASK` (0x4A) | 書き込みマスク（後段で要る） |
| `CSRR` (0xE0) | カーソル位置読み出し |
| ステータスレジスタ | 今のモックを本物に |

これでテキスト画面は**正しく**動く。グラフィック画面はスレーブ GDC の
START/SCROLL/PITCH だけで表示できる（描画は GRCG が担う）。

### 第2期 — GRCG

タイルレジスタ 4 本 + モードレジスタ、4 プレーン同時書き込み。
PC-98 ソフトのグラフィック描画の主役はこちら。

### 第3期以降 — 描画プロセッサ（やらない、当面）

`VECTW`/`VECTE`（線分・円弧・矩形）、`TEXTW`/`TEXTE`（パターン）、
`WRITE`/`READ`（GDC 経由の VRAM アクセス）、`LPEN`。

**理由**: 面積が大きく、PC-98 ソフトの大半は GRCG + 直接書き込みで描く。
BIOS の一部が使うので、必要が実証されてから実装する。

> ⚠ これは推測を含む判断である。「使わない」の根拠は PC-98 の一般的な
> プログラミング慣習であって、このツリーで測定したものではない。BIOS が
> 描画コマンドを発行して固まるなら、この判断を先に見直すこと。
> 検出方法: GDC のコマンド FIFO に未実装コマンドが来たら post_monitor に
> 記録する（第1期で入れる）。

## 構造

```
                      ports 0x60-0x6E (master)     ports 0xA0-0xAE (slave)
                                │                            │
                        ┌───────▼────────┐          ┌────────▼───────┐
                        │  pc98_gdc      │          │  pc98_gdc      │
                        │  (MASTER=1)    │          │  (MASTER=0)    │
                        │  cmd FIFO      │          │                │
                        │  param RAM     │          │                │
                        │  display regs  │          │                │
                        └───────┬────────┘          └────────┬───────┘
                   start/pitch/ │ partitions                 │ start/pitch
                   cursor       │                            │ partitions
                        ┌───────▼────────┐          ┌────────▼───────┐
                        │ pc98_text_     │          │ (GVRAM 表示、  │
                        │ render         │          │  第2期)        │
                        └────────────────┘          └────────────────┘
```

一つのモジュールを二度インスタンス化する。マスタとスレーブの違いは
パラメータ一つ（同期生成を出すか、ポートのベースアドレス）だけで、
コマンド解釈は同一。

**同期生成は GDC から出さない。** `pc98_video_timing` が 640×400 24.83 kHz を
作っており、実機と違ってこれは動いている。GDC の SYNC パラメータは
**受け取って記録するが、ラスタは既存のタイミング生成器が出す**。
理由: ラスタを GDC に移すと、今動いている画面が全部リスクに晒される。
SYNC パラメータが既存のタイミングと食い違ったときに何が起きるかは、
食い違いを検出して post_monitor に出すところから始める。

## 挿入点

`pc98_text_render` は今 `tv_cell` を `hcount`/`vcount` から計算している
（開始アドレス 0、分割なし、カーソルなし）。ここが唯一の変更点:

```
tv_cell = gdc_start_for_line(vcount) + column
```

`gdc_start_for_line` は SCROLL の分割表（SAD/LEN × 4）から行に対応する
領域を引く。分割が一つで SAD=0 なら現在の挙動と同一になるので、
**GDC が何も設定されていない状態でも今の画面が出る**ことが退行テストになる。

## 検証

1. `tb_pc98_gdc` — コマンド FIFO とパラメータ RAM の単体。np2kai の
   `gdc.c` / `gdc_sub.c` の挙動に対して、コマンド列 → レジスタ値を照合
2. `tb_pc98_text` の拡張 — SAD/LEN を振って `tv_cell` の列を確認。
   分割 1・SAD 0 で現行と一致すること（退行）
3. `tb_pc98_boot` — 実 ITF が GDC に何を書くかを記録し、未実装コマンドが
   来ないことを確認。**来たら第3期の判断を見直す**
4. 実機 — カーソルが出る、画面がスクロールする

## 面積の予算と撤退線

第1期の見込み: **600〜1,200 ALM**（コマンド FIFO、パラメータ RAM 54 バイト、
表示レジスタ、分割の引き当て。描画プロセッサなし）。

空き 1,480 に対して収まる見込みだが、**測ってから次へ進む**。
`scripts/measure_core.sh pc98_gdc` で単体を測り、実ビルドのフィットで
設計内の値を確認する。

1,480 を超えたら、次の順で予算を作る:
`post_monitor` 484（000KB 解決後）→ audio の部分削減 → `floppy` 833（PC-98 FDC 移行時）。
