# PC-98 I/O ポートマップ(NP2kai ソース由来)

**出典**: `/Users/hiroya/NP2kai`(AZO234/NP2kai)の `iocore_attach*` 呼び出しと、
各デバイス実装(`io/`, `cbus/`, `diskimage/`)の読解。コードは転載していない。
**用途**: PC/AT チップセット(8259A×2 / 8253 / 8237 / 8255 / FDC)を PC/AT 番地で
デコードしている現行 FPGA 実装を、PC-98 番地へ移すためのチップセレクト設計資料。

**読み方の約束**

- 「R」= IN で意味がある、「W」= OUT で意味がある、「R/W」= 両方。
- 「未接続」= NP2kai がハンドラを張っていない。**IN は 0xFF、OUT は捨てられる**
  (`io/iocore.c` の `definp8`/`defout8`)。実機がそうだという保証ではない。
- 「NP2 の推定」と書いた行は、NP2kai のコードから機能は読めるが
  実機ドキュメントで裏を取っていない、という意味。
- 本書は **NP2kai がどう振る舞うか** の記述である。NP2kai 自身が近似・省略している
  箇所は §12 に列挙した。実 ITF ROM のディスアセンブルはしていない。

## 1. アドレスデコードのモデル(これを最初に読むこと)

NP2kai は I/O ハンドラを 4 つのクラスで登録する。クラスが
**「上位アドレスをどこまで見るか」= チップセレクトの広さ**を決めている。

| 登録関数 | NP2 の呼び名 | 実際のデコード幅 |
|---|---|---|
| `iocore_attachcmn{out,inp}[ex]` | 8bit decode | **A7..A0 のみ**。A15..A8 は don't care |
| `iocore_attachsys{out,inp}[ex]` | システム I/O / 10bit decode | A7..A0 + **A11=A10=0** を要求。A9,A8 と A15..A12 は見ない |
| `iocore_attachsnd{out,inp}` | サウンド I/O / 12bit decode | A11..A0。A15..A12 は don't care |
| `iocore_attach{out,inp}` | 拡張 I/O / 16bit decode | A15..A0 完全一致 |

`sys` の実装は `io/iocore.c` の `iocore_build()` で、
上位バイト `i` について `(i & 0x0C) == 0` のページに「システムテーブル」を割り当てている。
つまり **A11:A10 == 00** が唯一の条件で、A9/A8 は検査されない。
その結果 NP2 では 0x0031 と 0x0131 と 0x1031 が同じレジスタに当たる。

> **PC-9821 ビルドでは違う。** `SUPPORT_PC9821` 時のマスクは `0x0C | (np2cfg.sysiomsk >> 8)` で、
> `sysiomsk` の既定値は 0xFF00(`pccore.c` の `np2cfg` 初期化子)。よってマスクは 0xFF となり、
> **上位バイト == 0x00 のページだけ**がシステム I/O になる = 16bit フルデコード。
> **FPGA 実装はこちら(フルデコード)を採るべき**。A9..A8 を無視する 9801 ビルドの挙動は
> NP2 の簡略化であって、真似する理由がない。

### 1.1 `*ex` 版のマスクとチップセレクトの導出

`iocore_attachsysoutex(port, mask, func[], nfuncs)` の意味:

- `port` と `mask` は **下位 8 ビットだけ**が使われる(`attachoutex()` が `& 0xff` する)。
- `i & (mask & 0xff) == (port & 0xff)` を満たす下位バイト `i` すべてにハンドラを張る。
- 該当する `i` を昇順に並べ、`func[]` を先頭から順に割り当て、`nfuncs` で折り返す
  (`nfuncs` は 2 の冪であることが前提)。

したがって:

- **マスクに立っていないビット = そのデバイス内のレジスタ選択ビット**。
- 「マスクに立っていないビットの数」 > `log2(nfuncs)` のとき、**余ったビットは don't care になり
  エイリアスが生じる**。実機がそのエイリアスを持つかは NP2 のコードからは分からない。

例: PIC は `port=0x0000, mask=0x0CF1, nfuncs=2`。下位マスク 0xF1 なので
自由ビットは A3,A2,A1。該当する `i` は 0x00,02,04,06,08,0A,0C,0E の 8 個で、
2 個の関数を交互に割り当てる → A1 がレジスタ選択、A3 がマスタ/スレーブ選択、
**A2 は don't care(エイリアス)**。PC-9821 ビルドでは `nfuncs=4` かつ後ろ 2 個が NULL なので
A2=1 は未接続になる = A2 もデコードされる。

### 1.2 16bit(ワード)アクセスの扱い

`iocore_out16`/`iocore_inp16` は `port & 0x0C00` が 0 のとき、下位バイトごとに
特別扱いをする(`io/iocore16.tbl` の `ioterminate` テーブル)。
**8 ビット幅のデバイスに 16 ビット IN/OUT した時に何が返るか** の定義であり、
バス上のフローティング値を NP2 が定数で模している。

| 分類 | 対象ポート(下位バイト) | OUT 16bit | IN 16bit |
|---|---|---|---|
| `TERM_WORD` | 0x01,03,05,07,09,0B,0D,0F, 0x15,0x19,0x1F, 0x21,23,25,27,29, 0xF2,0xF6 | **何も書かない**(丸ごと無視) | 定数 **0x2588** |
| `TERM_ACTIVE` | 0xD0,D2,D4,D6,D8,DC,DE | 下位バイトのみ | 上位 = 直前の AX 上位バイト |
| `TERM_PLUS` | 0x30,32,34,36, 0x40,42,44,46, 0x71,75,79, 0xAD,0xAF | 下位バイトのみ | 上位 = 0xFF |
| `TERM_MINUS` | 0x60,62,64,68,6A,6C, 0x70,72,74,76,7A,7C, 0xA0,A2,A4,A6,A8,AC | 下位バイトのみ | 上位 = 0x00 |
| `TERM_EXT08` | 0x20,22,24,26 | 下位バイトのみ | 上位 = 0x08 |
| 上記以外 | — | port と port+1 に 2 回の 8bit アクセス | 同左 |

真に 16 ビット幅で扱われるのは EGC(0x04A0-0x04AF、`egc_w16`/`egc_r16`)と
ARTIC(0x005C-0x005F、`artic_r16`)だけ。

> DMA レジスタ群(0x01-0x29 の奇数)が `TERM_WORD` に入っているのは重要で、
> **16 ビット OUT では下位バイトすら書かれない**。ソフトが 16bit OUT で
> DMA を叩いてこないことを前提にした割り切りである。実機は 8 ビットバス側で
> 下位だけ書かれるはずで、ここは NP2 の独自解釈と見るべき。

## 2. PC/AT → PC-98 移設 早見表

現行実装のチップセレクトを移す先。詳細は各章。

| チップ | PC/AT 番地 | **PC-98 番地** | レジスタ選択 | 備考 |
|---|---|---|---|---|
| 8259A マスタ | 0x20,0x21 | **0x00, 0x02** | A1 | A0=0 固定(偶数番地) |
| 8259A スレーブ | 0xA0,0xA1 | **0x08, 0x0A** | A1 | チップ選択は A3 |
| 8237A DMA | 0x00-0x0F | **0x01-0x1F の奇数** | A4..A1 | A0=1 固定(奇数番地) |
| DMA ページ | 0x80-0x8F | **0x21,0x23,0x25,0x27** | A2..A1(ch 順が入れ替わる) | §5.2 |
| 8253/8254 | 0x40-0x43 | **0x71,0x73,0x75,0x77** | A2..A1 | A0=1 固定 |
| 8255 システム | 0x60,0x61,0x64 | **0x31,0x33,0x35,0x37** | A2..A1 | A0=1 固定 |
| FDC (µPD765A) | 0x3F0-0x3F7 | **0x90,0x92,0x94**(1MB系) / **0xC8,0xCA,0xCC**(640KB系) | A2..A1 | §3 |
| キーボード | 0x60,0x64 | **0x41, 0x43**(8251) | A1 | PC-98 は 8251 シリアル |
| NMI マスク | 0x70 bit7 | **0x50(禁止) / 0x52(許可)** | A1 | データは無関係 |
| A20 / CPU リセット | 0x64,0x92 | **0xF0(リセット), 0xF2(A20 ON)** | A1 | §10 |

**PC-98 の一番大きな構造的違い**: システムボードの 8 ビットデバイスは
**偶数番地と奇数番地で別デバイスに分かれている**。
0x00-0x0F では偶数=PIC / 奇数=DMA、0x30-0x3F では偶数=8251(RS-232C) / 奇数=8255、
0x40-0x4F では偶数=プリンタ / 奇数=キーボード 8251、
0x70-0x7F では偶数=CRTC+GRCG / 奇数=8253、
0xA0-0xAF では偶数=グラフィック GDC / 奇数=CG-ROM。
**A0 は「どのチップか」の一部**であって、レジスタ選択ではない。ここを PC/AT の
感覚のまま作ると必ず衝突する。

## 3. ★最重要 4 ポート: 0x00BE / 0x0090 / 0x0092 / 0x0094

この 4 本は FDC インタフェース周りで、初期化中にポーリングされる。
**0xBE の返す値と 0x90 の RQM ビットを間違えると起動シーケンスが進まない。**

### 3.1 全体像

PC-98 は **2 系統の FDC インタフェースを持ち、同じ µPD765A を共有する**。

| 系統 | ステータス | データ | 制御/状態 | 割り込み | DMA ch |
|---|---|---|---|---|---|
| 1MB(2HD, 1.2MB) | **0x90** | **0x92** | **0x94** | IRQ11 | 2 |
| 640KB(2DD, 720KB) | 0xC8 | 0xCA | 0xCC | IRQ10 | 3 |

どちらの系統が生きているかを決めるのが **0x00BE**。
NP2kai(`io/fdc.c`)では全アクセスの先頭で

- `((port >> 4) ^ fdc.chgreg) & 1` が 0 でなければ **IN は 0xFF を返し、OUT は捨てる**

という判定が入る。`port>>4` の bit0 は 0x9x なら 1、0xCx なら 0。
つまり **`0xBE` の bit0 が 1 なら 0x90 系だけが応答し、0xC8 系は 0xFF を返す。0 ならその逆**。
再実装でここを両方応答させると、ITF/BIOS のインタフェース検出が誤動作する。

**登録の実際**(`fdc_bind()`):

- `iocore_attachcmn{out,inp}ex(0x0090, 0x00F9, tbl, 4)` → 下位マスク 0xF9、自由ビットは A2,A1。
  該当は 0x90,0x92,0x94,0x96。**8bit デコード**(上位バイト don't care)。
- 同じ表を `0x00C8, 0x00F9` にも張る → 0xC8,0xCA,0xCC,0xCE。
- `iocore_attachsys{out,inp}ex(0x00BE, 0x0CFF, tbl, 1)` → 下位マスク 0xFF なので 0xBE 一点のみ。
  **sys デコード**(A11:A10=00 を要求)。

### 3.2 0x00BE — FDD インタフェース切替レジスタ(R/W)

`fdc_obe` / `fdc_ibe`。実体は 1 バイトのラッチ `fdc.chgreg`。

**Write(bit 割り当て)**

| bit | 意味 | 効果 |
|---|---|---|
| 0 | **I/F 選択** | 1 = 0x90/0x92/0x94 を有効(1MB系)、0 = 0xC8/0xCA/0xCC を有効(640KB系) |
| 1 | **メディアモード** | 1 = 2HD、0 = 2DD(`CTRL_FDMEDIA` に反映) |
| 2 | モータ制御の許可 | `fdc.chgreg & 4` のとき、0x94 bit3 の 0→1 でレディなドライブに AI 割り込みを立てる |
| 3-7 | NP2 は保持するだけ | 読み出しには反映されない(下記) |

**Read(返却値)**

```
返り値 = 0xF8 | (chgreg & 3)
```

| bit | 値 |
|---|---|
| 7..4 | **常に 1** |
| 3 | **常に 1**(コード上ハードコードの `| 8`) |
| 2 | **常に 0**(書いた値は読めない) |
| 1 | 直前に書いたメディアモード |
| 0 | 直前に書いた I/F 選択 |

- **リセット値**: `fdc_reset()` が `fdc.chgreg = 3` を設定 → **読み出しは 0xFB**、
  同時に `CTRL_FDMEDIA = 2HD`。つまり電源投入直後は **1MB インタフェースが選択済み**。
- **フロッピードライブが 1 台もない機械でも返る値は同じ(0xFB)**。
  このポートはドライブの有無をまったく参照しない。ドライブ有無は
  設定値 `fddequip`(既定 0x03 = ドライブ 0,1 実装)経由で
  FDC コマンドの結果バイトにだけ現れる(§3.6)。
- **再実装の必須条件**: bit3 を 1 で返すこと、bit1:0 が書いた通りに読めること。
  0x00 や 0xFF を返す実装は不可。

### 3.3 0x0090 — FDC メインステータスレジスタ(R のみ)

µPD765A の Main Status Register。`fdc_i90` は `fdc.status` をそのまま返す
(I/F 選択が外れていれば 0xFF)。**書き込みは未接続 = 捨てられる**。

| bit | 名前 | 意味 |
|---|---|---|
| 7 | **RQM** | 1 = データレジスタ(0x92)がアクセス可能 |
| 6 | **DIO** | 0 = CPU→FDC 方向(書ける)、1 = FDC→CPU 方向(読める) |
| 5 | **NDM (EXM)** | 1 = ノン DMA 実行中 |
| 4 | **CB** | 1 = コマンド実行中(Busy) |
| 3..0 | **D3..D0** | ドライブ 3..0 のシーク中フラグ |

- **リセット値 / アイドル時**: `fdcstatusreset()` が `status = FDCSTAT_RQM` のみを立てる
  → **0x80**。ドライブ 0 台でも 0x80。
- **ここが起動の関門**: ソフトは「RQM が立つまで待つ」ループを回す。
  0x00 を返し続けると**ハングする**。0xFF を返すと RQM|DIO|CB が同時に立ち、
  「読み出し可能なリザルトがある」と誤認されて別の経路で詰まる。
  **コマンドを受け付けられる状態では 0x80 を返すこと。**
- 結果フェーズに入るときは `status &= 0x0F` の後に `RQM|CB|DIO`(=0xD0)と
  対象ドライブビットが立つ。つまり結果読み出し中は **0xD0 | (1<<unit)**。

### 3.4 0x0092 — FDC データレジスタ(R/W)

`fdc_o92` / `fdc_i92`。

- **Write**: `(status & (RQM|DIO)) == RQM` のときだけ `fdc_datawrite()` へ渡す。
  それ以外の状態の書き込みは黙って捨てられる。
  コマンド第 1 バイト → パラメータバイト列(バイト数は `FDCCMD_TABLE` による)→ 実行。
- **Read**: `(status & (RQM|DIO)) == (RQM|DIO)` のときだけ次のリザルトバイトを返す。
  条件を満たさないときは **`fdc.lastdata`(最後に返した値)を返す**。
  リセット直後の `lastdata` は 0(`ZeroMemory`)。
- **ドライブ 0 台でもポート自体の挙動は変わらない**。ドライブ不在は
  コマンド結果(ST0/ST3)にだけ出る。

**コマンド別パラメータバイト数**(`FDCCMD_TABLE`、index = cmd & 0x1F):

| cmd | 名前 | パラメータ数 |
|---|---|---|
| 0x02 | READ DIAGNOSTIC | 8 |
| 0x03 | SPECIFY | 2 |
| 0x04 | SENSE DEVICE STATUS | 1 |
| 0x05 | WRITE DATA | 8 |
| 0x06 | READ DATA | 8 |
| 0x07 | RECALIBRATE | 1 |
| 0x08 | SENSE INTERRUPT STATUS | 0 |
| 0x09 | WRITE DELETED DATA | 8 |
| 0x0A | READ ID | 1 |
| 0x0C | READ DELETED DATA | 8 |
| 0x0D | WRITE ID (FORMAT) | 5 |
| 0x0F | SEEK | 2 |
| 0x11/0x19/0x1D | SCAN EQUAL 系 | 8 |
| その他 | INVALID | 0(即 ST0=0x80 を 1 バイト返す) |

### 3.5 0x0094 — FDC 制御レジスタ(W) / インタフェース状態(R)

**Write(`fdc_o94`)** — 書いた値は `fdc.ctrlreg` に丸ごと保持される。

| bit | 意味(NP2 の実装から読めるもの) |
|---|---|
| 7 | **RESET**。0→1 の変化で FDC 内部状態をリセット(status を 0x80 に戻す)。同時に bit3 が 1 なら、4 ドライブ分の遅延割り込みを仕込む |
| 6 | **強制 READY**。ディスクが入っていなくても READY 扱いにする(SENSE DEVICE STATUS / RECALIBRATE の分岐に効く) |
| 5 | NP2 未使用 |
| 4 | **DMA イネーブル**。変化を検出すると status をリセットし DMA レディを落とす |
| 3 | **モータ ON**。0x00BE bit2 が立っているとき、0→1 で「レディなドライブ」に AI(0xC0\|unit)割り込みを立てる |
| 2..0 | NP2 未使用 |

**Read(`fdc_i94`)** — 状態は一切参照せず、ほぼ定数を返す:

```
ret = 0x40
if (アクセスされたポートの bit4 == 0)      // すなわち 0xCC 側
    ret |= 0x20            // DMA
    ret |= 0x10            // READY
if (DIPSW1 の bit3 が 1)  ret |= 0x04      // 内蔵優先
else                      ret |= 0x08      // 外付け優先
```

| bit | 0x94(1MB系)での値 | 0xCC(640KB系)での値 | 意味 |
|---|---|---|---|
| 7 | 0 | 0 | — |
| 6 | **1**(固定) | **1** | NP2 はここを常に 1 にする |
| 5 | 0 | 1 | DMA |
| 4 | 0 | 1 | READY |
| 3 | `dipsw[0]` bit3 が 0 なら 1 | 同左 | 外付け FDD 優先 |
| 2 | `dipsw[0]` bit3 が 1 なら 1 | 同左 | 内蔵 FDD 優先 |
| 1..0 | 0 | 0 | — |

- **NP2 の DIP スイッチ既定値は `dipsw[0] = 0x3E`** で bit3 = 1。
  (NP2 のコメント慣習では `dipsw[0]` bit N がスイッチ 1-(N+1) に対応し、
  **ビットが立っている = スイッチ OFF**。`bios/bios.c` の `!(dipsw[0] & 1)` に
  「dipsw1-1 on」と注記されているのが根拠。)
  したがって **0x94 の読み出しは 0x44、0xCC の読み出しは 0x74** が既定。
- **ドライブが 1 台も無い機械でも同じ値**。このポートはドライブ状態を見ない。
- I/F 選択(0xBE bit0)が外れていれば **0xFF**。
- 0x96 / 0xCE はマスクにはヒットするがハンドラが NULL → **読み 0xFF、書き無視**。

### 3.6 「ドライブが 1 台も無い」ときに何が変わるか

**上の 4 ポートの直接の返り値は一切変わらない。** 変わるのは FDC コマンドの結果だけで、
NP2 は `fdc.equip`(= 設定 `fddequip`、既定 0x03)のビットで判定する。

| コマンド | ドライブ非実装(equip ビット = 0)のときの結果 |
|---|---|
| SENSE DEVICE STATUS (0x04) | ST3 = `0x80 \| (hd<<2) \| unit`。bit7(FT/Fault)が立ち、READY(0x20)・TRK0(0x10)・WP(0x40)は落ちる |
| RECALIBRATE (0x07) | ST0 に `SE(0x20) \| IC0(0x40)` と、0x94 bit6(強制 READY)が立っていなければ `NR(0x08)`。強制 READY なら NR ではなく `EC(0x10)` |
| SENSE INTERRUPT STATUS (0x08) | 保留割り込みが無ければ **ST0 = 0x80(IC=10, invalid)を 1 バイト**。これは 765A の規定どおりで、BIOS のリセット後ループを抜けるのに必須 |
| READ/WRITE 系 | `fdd_diskready()` が偽なので ST0 に `IC0 \| NR`、7 バイトのエラーリザルトを返す |

**再実装の指針**: ドライブ 0 台の板でも 0xBE=0xFB / 0x90=0x80 / 0x94=0x44 を返し、
コマンドは受け付けて上表の ST0/ST3 を返す。ポート側でハングさせない。

### 3.7 関連: 0x04BE — 1.44MB モードレジスタ(R/W、16bit デコード)

`fdc.support144`(PC-9821 ビルドでは常に有効、それ以外は設定 `usefd144`)が
真のときだけ張られる。

- **Write**: 値を `fdc.reg144` に保存。bit4 が 1 のとき `rpm[(dat>>5)&3] = dat & 1`
  (bit6:5 でドライブ選択、bit0 が RPM 300/360 の別)。
- **Read**: `rpm[(reg144>>5)&3] | 0xFE` → **0xFE か 0xFF**。リセット直後は 0xFE。
- 未サポート構成では未接続 = **0xFF**。この差(0xFE か 0xFF か)が
  1.44MB 対応機かどうかの判定に使われている。

## 4. 割り込みコントローラ 8259A ×2

`io/pic.c`。`iocore_attachsys{out,inp}ex(0x0000, 0x0CF1, tbl, 2)`
(PC-9821 ビルドは `nfuncs=4` で後ろ 2 個 NULL)。

| ポート | R/W | デバイス / レジスタ | 選択ビット |
|---|---|---|---|
| 0x00 | W | **マスタ 8259A**, A0=0: ICW1 / OCW2 / OCW3 | A3=0 → マスタ、A1=0 → A0=0 |
| 0x00 | R | マスタ, IRR または ISR(OCW3 の RIS ビット次第) | 同上 |
| 0x02 | W | マスタ, A0=1: ICW2/ICW3/ICW4 または OCW1(IMR) | A1=1 → A0=1 |
| 0x02 | R | マスタ, IMR | 同上 |
| 0x04, 0x06 | R/W | **マスタのエイリアス**(A2 が don't care)。PC-9821 ビルドでは未接続 | — |
| 0x08 | R/W | **スレーブ 8259A**, A0=0 | A3=1 → スレーブ |
| 0x0A | R/W | スレーブ, A0=1 | — |
| 0x0C, 0x0E | R/W | スレーブのエイリアス。PC-9821 ビルドでは未接続 | — |

**チップセレクトの書き方**: `CS = (A11:A10 == 00) && (A7:A4 == 0000) && (A0 == 0)`、
`slave_sel = A3`、`8259_A0 = A1`。A2 は 9821 では 0 を要求する。

**書き込みデータのデコード**(`pic_o00`、A0=0 側):

- `dat & 0x18 == 0x00` → **OCW2**。bit7=R, bit6=SL, bit5=EOI, bit2:0=レベル。
- `dat & 0x18 == 0x08` → **OCW3**。bit0=RIS, bit1=RR, bit2=P, bit5=SMM, bit6=ESMM。
  RR=0 のときは RIS の既存値が保持される(書き換わらない)。
- それ以外(bit4=1)→ **ICW1**。IMR/IRR/OCW3/優先度がクリアされ、
  以後 A0=1 側への書き込みが ICW2→ICW3→(ICW1 bit0 が 1 なら)ICW4 の順に入る。
  シーケンス長は `3 + (ICW1 & 1)` バイト。

**A0=1 側**(`pic_o02`): ICW シーケンス中なら ICW、そうでなければ **IMR(OCW1)**。

**IN の内容**: A0=0 → OCW3 の RIS が 0 なら IRR、1 なら ISR。A0=1 → IMR。
**ポーリングモード(OCW3 bit2 = P)は実装されていない。**

**リセット値**(`pic_reset()`。実機の電源投入値ではなく NP2 の既定値):

| | ICW1 | ICW2(ベクタ) | ICW3 | ICW4 | IMR |
|---|---|---|---|---|---|
| マスタ | 0x11 | 0x08 | 0x80 (IR7 にスレーブ) | 0x1D | 0x7D |
| スレーブ | 0x11 | 0x10 | 0x07 (カスケード ID 7) | 0x09 | 0x71 |

→ **PC-98 の IRQ0-7 は INT 0x08-0x0F、IRQ8-15 は INT 0x10-0x17**。
カスケードは **マスタ IR7**(PC/AT の IR2 ではない)。ここは PC/AT からの移設で
必ず踏む差分。

## 5. DMA コントローラ 8237A

`io/dmac.c`。`iocore_attachsys{out,inp}ex(0x0001, 0x0CE1, tbl, 16)`。
下位マスク 0xE1 → 自由ビットは A4,A3,A2,A1、A0=1 固定。
16 個の関数を昇順に割り当てるのでエイリアスは無い。

**チップセレクト**: `CS = (A11:A10 == 00) && (A7:A5 == 000) && (A0 == 1)`、
`reg_sel = A4:A1`。

### 5.1 本体レジスタ(0x01-0x1F の奇数)

| ポート | R/W | レジスタ | 選択ビット |
|---|---|---|---|
| 0x01 | R/W | **ch0 メモリアドレス**(下位/上位を LOW/HIGH フリップフロップで交互) | A4:A3=00, A2=0(ch), A1=0 |
| 0x03 | R/W | **ch0 転送カウント** | A1=1 |
| 0x05 | R/W | ch1 メモリアドレス | A3:A2=01 |
| 0x07 | R/W | ch1 転送カウント | |
| 0x09 | R/W | ch2 メモリアドレス | A3:A2=10 |
| 0x0B | R/W | ch2 転送カウント | |
| 0x0D | R/W | ch3 メモリアドレス | A3:A2=11 |
| 0x0F | R/W | ch3 転送カウント | |
| 0x11 | **R のみ** | **ステータスレジスタ**。読むと下位ニブル(TC フラグ)がクリアされる | A4=1, A3:A1=000 |
| 0x11 | W | **未接続 = コマンドレジスタは未実装**(§12 参照) | |
| 0x13 | W | ソフトウェア DMA リクエスト | |
| 0x15 | W | **単一チャネルマスク**。bit1:0=ch、bit2=1 でマスク、0 で解除 | |
| 0x17 | W | **モードレジスタ**。bit1:0=ch。NP2 が実際に見るのは bit5(アドレス増減)のみ | |
| 0x19 | W | **LOW/HIGH フリップフロップクリア**(データ値は無関係) | |
| 0x1B | W | **マスタクリア**。全 ch のアドレス/カウントを 0、マスクを 0x0F に | |
| 0x1D | W | 全マスク解除(mask = 0) | |
| 0x1F | W | **全チャネルマスク書き込み**(下位 4 ビットが ch3..ch0) | |
| 0x13,0x15,0x17,0x19,0x1B,0x1D,0x1F | R | **未接続 → 0xFF** | |

- **アドレス/カウントのバイト順**: 1 個の共有フリップフロップ `dmac.lh` が
  「次は下位か上位か」を持つ。**チャネルごとではなくコントローラで 1 個**。
  0x19 への書き込みで下位に戻る。読み出しでもフリップフロップは反転する。
- **リセット値**(`dmac_reset()`): 全レジスタ 0、`lh` = LOW、**mask = 0x0F(全 ch マスク)**。

### 5.2 ページ(バンク)レジスタ

`iocore_attachsysoutex(0x0021, 0x0CF1, tbl, 8)`。下位マスク 0xF1 →
自由ビットは A3,A2,A1。該当は 0x21,23,25,27,29,2B,2D,2F。

| ポート | R/W | レジスタ | 備考 |
|---|---|---|---|
| 0x21 | **W のみ** | **ch1** のバンク(A23..A16) | ch 番号 = `((port>>1) + 1) & 3` |
| 0x23 | W | **ch2** のバンク | |
| 0x25 | W | **ch3** のバンク | |
| 0x27 | W | **ch0** のバンク | |
| 0x29 | W | **DMA バウンダリ/拡張モード**。bit1:0=ch、bit3:2 を `bound` に格納 | §12 |
| 0x2B,0x2D,0x2F | — | 未接続 | |
| 0x21-0x2F | R | **すべて未接続 → 0xFF** | |

**ch 番号が 1,2,3,0 の順に並ぶ**のが PC-98 の癖。A2:A1 の値を `n` とすると
`ch = (n + 1) mod 4`。

- **16 ビット CPU コア(V30)では書いた値の下位 4 ビットだけが有効**(20 ビットアドレス)。
  IA-32 コアでは 8 ビットすべて(24 ビットアドレス)。
- `0x0E05 / 0x0E07 / 0x0E09 / 0x0E0B`(W のみ、16bit デコード)は
  **32 ビット DMA 拡張のバンク上位バイト(A31..A24)**。それぞれ ch0/ch1/ch2/ch3。
  ハンドラは `ch = ((port - 5) & 7) >> 1` で算出しており、値の bit7 はマスクされる(25 ビット目以上は 0x7F)。

### 5.3 DMA チャネル割り当て

| ch | デバイス |
|---|---|
| 0 | SASI HDD |
| 1 | 空き(サウンドボード等が使う) |
| 2 | **1MB FDD(2HD)** |
| 3 | **640KB FDD(2DD)** |

## 6. タイマ 8253 / 8254(µPD8253C, IA-32 ビルドでは µPD71054 相当)

`io/pit.c`。`iocore_attachsys{out,inp}ex(0x0071, 0x0CF1, tbl, 4)`。
下位マスク 0xF1 → 自由ビットは A3,A2,A1、A0=1 固定。
`nfuncs=4` なので **A3 は don't care → 0x79-0x7F にエイリアスが生じる**。

**チップセレクト**: `CS = (A11:A10 == 00) && (A7:A4 == 0111) && (A0 == 1)`、
`counter_sel = A2:A1`。A3 は 9801 では don't care。

| ポート | R/W | レジスタ | 用途 |
|---|---|---|---|
| 0x71 | R/W | **カウンタ 0** | システムタイマ → IRQ0 |
| 0x73 | R/W | **カウンタ 1** | BEEP(ブザー)周波数 |
| 0x75 | R/W | **カウンタ 2** | RS-232C ボーレート |
| 0x77 | **W のみ** | **コントロールワード** | R は未接続 → 0xFF |
| 0x79,0x7B,0x7D,0x7F | R/W | 上記のエイリアス(A3 が無視される) | |
| 0x3FD9 / 0x3FDB / 0x3FDD / 0x3FDF | R/W | **同じ 4 レジスタの 16bit デコード別名**。0x3FDF は W のみ | 高解像度モード機 |

**読み出しのチャネル選択**は `(port >> 1) & 3` なので A2:A1。

**コントロールワード**(`pit_o77`):

- bit7:6 = チャネル(3 は µPD71054 の Read-Back コマンド)。
- bit5:4 = RL(00=ラッチ, 01=下位のみ, 10=上位のみ, 11=下位→上位)。
- bit3:1 = モード、bit0 = BCD(NP2 は BCD を無視)。
- **チャネル 0 へ書くと 8259 マスタの IRR bit0 がクリアされる**
  (`pic.pi[0].irr &= ~1`)。実機の挙動を模したもので、
  タイマ割り込みの取りこぼし防止に効いている。**再実装で落とすと挙動が変わる。**

**カウンタ読み出し**(`pit_getstat`): ラッチ済みならラッチ値、
そうでなければ現在値。RL=11 のときは下位→上位の順にトグルする内部フラグを持つ。
µPD71054 ビルドではステータスラッチ(bit4=0 の Read-Back)にも応答する。

**リセット値**(`itimer_reset()`): 全ゼロ後に
ch0.ctrl=0x16、ch1.value=1229(8MHz 系なら 998)、ch2.ctrl=0x36。
ch3/ch4 はサウンドボード用の内部カウンタで I/O には出ない。

**入力クロック**: PC-98 は 2.4576MHz(5/10MHz 系)または 1.9968MHz(8MHz 系)。
NP2 は `pccore.multiple` によるクロック換算で近似しており、
**分周値そのものはエミュレートしていない**(§12)。

## 7. システムポート 8255(PPI)

`io/sysport.c`。`iocore_attachsys{out,inp}ex(0x0031, 0x0CF1, tbl, 4)`。
自由ビットは A3,A2,A1、`nfuncs=4` → **A3 は don't care(0x39-0x3F にエイリアス)**。

**チップセレクト**: `CS = (A11:A10 == 00) && (A7:A4 == 0011) && (A0 == 1)`、
`8255_A1A0 = A2:A1`。

| ポート | R/W | レジスタ | 内容 |
|---|---|---|---|
| 0x31 | **R のみ** | **ポート A** | DIP スイッチ 2 の生値(`pccore.dipsw[1]`、既定 **0xE3**)。W は未接続 |
| 0x33 | **R のみ** | **ポート B** | bit3 = DIPSW1-1 の反転、bit7:5 = RS-232C ステータス、bit0 = µPD4990 のシリアル出力。W は未接続 |
| 0x35 | R/W | **ポート C** | 下表 |
| 0x37 | **W のみ** | **コントロールワード(ビットセット/リセット)** | R は未接続 → 0xFF |
| 0x39,0x3B,0x3D,0x3F | R/W | エイリアス | |

**ポート C(0x35)のビット** — NP2 が実際に機能を割り当てているのは下位 4 ビットだけ:

| bit | 意味 |
|---|---|
| 0 | RS-232C 受信割り込み許可(RxRE)。`serial.c` が参照 |
| 1 | RS-232C 送信空割り込み許可(TxEE) |
| 2 | RS-232C 送信レディ割り込み許可(TxRE)。**変化を検出すると送信を起動する** |
| 3 | **ブザー制御。1 = 消音、0 = 発音**(`sound/beepc.c` が `(sysport.c & 8) ? 0 : 1`) |
| 7..4 | NP2 は保持するだけで何も駆動しない。**読み出しには書いた値がそのまま出る** |

- **リセット値**: `systemport_reset()` が **0xF9** を書く
  (bit0=1, bit3=1 → ブザー消音、bit7:4=1)。
- **0x35 の読み出しはラッチの読み戻し**。書いた値が必ず読めなければならない。

**コントロールワード(0x37)**: `(dat & 0xF0) == 0` のときだけ処理する。
つまり **ビットセット/リセット(BSR)のみ実装**、モード設定(bit7=1)は無視される。

```
bit3:1 = 操作するポート C のビット番号
bit0   = 1 でセット、0 でリセット
```

`bit==0x04`(bit2)のセット/リセットは RS-232C 送信を起こし、
`bit==0x08`(bit3)はブザーを再評価する。

> **注意**: 実機の 8255 では 0x37 に mode word(bit7=1)を書けばポートの入出力方向が
> 変わるが、NP2 はこれを完全に無視する。再実装でも BSR だけ実装すれば実用上は足りるが、
> mode word を書かれても壊れないようにしておくこと。

## 8. キーボードインタフェース(8251 USART)

`io/serial.c` の `keyboard_*`。`iocore_attachsys{out,inp}ex(0x0041, 0x0CF1, tbl, 2)`。
自由ビットは A3,A2,A1、`nfuncs=2` → **A2,A3 が don't care(0x45-0x4F にエイリアス)**。

**チップセレクト**: `CS = (A11:A10 == 00) && (A7:A4 == 0100) && (A0 == 1)`、
`8251_C/D = A1`。

| ポート | R/W | レジスタ |
|---|---|---|
| 0x41 | R | **受信データ**。読むと status bit1 が落ち、IRQ1 がリセットされる |
| 0x41 | W | `cmd & 1`(送信許可)が立っていればキーボードへ送信、立っていなければ **モード設定として保存** |
| 0x43 | R | **ステータス** |
| 0x43 | W | **コマンド** |
| 0x45,0x47,... 0x4F | R/W | エイリアス(奇数のみ) |

**ステータス(0x43 read)**: `keybrd.status | 0x85` を返す。8251 のステータス定義で:

| bit | 名前 | NP2 の値 |
|---|---|---|
| 7 | DSR | **常に 1** |
| 6 | SYNDET/BRKDET | status 由来(通常 0) |
| 5 | FE | status 由来 |
| 4 | OE | status 由来(バッファ溢れで 1) |
| 3 | PE | status 由来 |
| 2 | TxEMPTY | **常に 1** |
| 1 | **RxRDY** | 受信データがあると 1 |
| 0 | TxRDY | **常に 1** |

- **アイドル時の読み出しは 0x85**。ここを 0x00 にすると BIOS の送信待ちが抜けない。
- **リセット値**: `keyboard_reset()` で data=0xFF、mode=0x5E、status=0、cmd=0。

**コマンド(0x43 write)**:

- bit0 = 送信許可(TxEN)。これが 1 のとき 0x41 への書き込みがキーボードへ流れる。
- bit3 = 1→0 の変化で**リセット信号**(内部状態・バッファを全クリア)。
- bit4 = 1 でエラーフラグ(status の 0x38)をクリア。

**転送レート**: `keybrd.xferclock = realclock / 1920`。キーコードは
`keystat.c` が生成する PC-98 スキャンコード。

## 9. テキスト/グラフィック GDC(µPD7220 ×2)・CRTC・GRCG・パレット

### 9.1 テキスト GDC(マスタ)+ モードフリップフロップ

`io/gdc.c`。`iocore_attachsys{out,inp}ex(0x0060, 0x0CF1, tbl, 8)`。
自由ビットは A3,A2,A1、`nfuncs=8` → **エイリアス無し、A0=0 固定**。

**チップセレクト**: `CS = (A11:A10 == 00) && (A7:A4 == 0110) && (A0 == 0)`、
`reg_sel = A3:A1`。

| ポート | R/W | レジスタ |
|---|---|---|
| 0x60 | W | **GDC パラメータ**(FIFO へ、コマンドフラグなし) |
| 0x60 | R | **GDC ステータス** — 下表 |
| 0x62 | W | **GDC コマンド**(FIFO へ、コマンドフラグ付き。書いた時点で実行) |
| 0x62 | R | **GDC リードデータ**。送出データが無ければ **0xFF** |
| 0x64 | W | **VSYNC 割り込み要求のセット**(次の垂直帰線で IRQ2)。データは無関係 |
| 0x64 | R | 未接続 → 0xFF |
| 0x66 | — | 未接続 |
| 0x68 | W | **モードフリップフロップ 1**(ビットセット/リセット) |
| 0x68 | R | mode1 の現在値(**NP2 の拡張。実 9801 で読めるかは未確認**) |
| 0x6A | W | **モードフリップフロップ 2** + 拡張コマンド |
| 0x6A | R | mode2 の現在値(同上) |
| 0x6C | — | 未接続 |
| 0x6E | W | **CRT 15kHz 切替**(値 0 / 1 のみ意味を持つ) |
| 0x6E | R | 未接続 → 0xFF |

**GDC ステータス(0x60 / 0xA0 read)**:

| bit | 意味 |
|---|---|
| 7 | **常に 1**(NP2 がハードコード) |
| 6 | HBLANK 中 |
| 5 | **VSYNC 中** |
| 4 | (未使用) |
| 3 | DMA 実行中(スレーブ側のみ `s_drawing`) |
| 2 | **FIFO 空** |
| 1 | **FIFO フル** |
| 0 | データ READY(読み出し可能) |

- **ポーリング対象**: bit5(VSYNC)と bit2(FIFO 空)。
  bit7 を 0 にすると多くのソフトが誤動作する。
- 0x60 を読むたびに FIFO の処理が進む(`gdc_work()`)ので、
  実装では「読み出しで副作用がある」ことを覚えておく。

**モードフリップフロップ 1(0x68 write)**: `dat` が 0x00-0x0F のときのみ有効。

```
書き込む値 = (ビット番号 << 1) | セット/リセット
→ 内部ビット = 1 << ((dat >> 1) & 7)、dat bit0 が 1 でセット
```

| 内部 bit | 書く値(reset/set) | 意味(NP2 の参照箇所から確定) |
|---|---|---|
| 0 | 0x00 / 0x01 | ATRSEL — テキスト属性の解釈(背景色を使うか) |
| 1 | 0x02 / 0x03 | グラフィックのカラー/モノクロ |
| 2 | 0x04 / 0x05 | テキスト 80 桁 / 40 桁 |
| 3 | 0x06 / 0x07 | フォント選択(文字高)。CG ウィンドウのオフセットにも効く |
| 4 | 0x08 / 0x09 | 200 ライン(ライン倍化)モード |
| 5 | 0x0A / 0x0B | KAC — 漢字 CG アクセスモード |
| 6 | 0x0C / 0x0D | **メモリスイッチ書き込み許可**(`gdcs.msw_accessable`) |
| 7 | 0x0E / 0x0F | **画面表示イネーブル** |

**リセット値**(`gdc_biosreset()`): DIPSW1-1 が OFF なら **mode1 = 0x98**、
ON なら **0x80**(このとき `crt15khz = 3`)。

**モードフリップフロップ 2(0x6A write)**: `dat` が 0x00-0x07 のときは
ビットセット/リセット(内部 bit = `(dat>>1)&3`)。

| 内部 bit | 書く値 | 意味 |
|---|---|---|
| 0 | 0x00/0x01 | **16 色アナログモード**(パレットレジスタの意味が変わる) |
| 1 | 0x02/0x03 | NP2 は保持するだけ |
| 2 | 0x04/0x05 | **EGC モード**(bit3 と GRCG チップ種別 3 が前提) |
| 3 | 0x06/0x07 | 拡張グラフィック許可フラグ |

0x08 以上の値は拡張コマンド: 0x20/0x21(アナログ拡張)、0x40/0x41・0x80/0x81(プラズマ)、
0x82-0x85(ドットクロック)、0x68/0x69(256 色拡張)。

### 9.2 CRTC + GRCG

`io/crtc.c`。`iocore_attachsys{out,inp}ex(0x0070, 0x0CF1, tbl, 8)`。
自由ビットは A3,A2,A1、`nfuncs=8` → エイリアス無し、A0=0 固定。

| ポート | R/W | レジスタ |
|---|---|---|
| 0x70 | W | **CRTC `PL`**(ラスタ数 - 1。下位 5 ビットのみ有効) |
| 0x72 | W | CRTC `BL`(ブランキング) |
| 0x74 | W | CRTC `CL`(カーソル/行間) |
| 0x76 | W | CRTC `SSL`(スキップライン) |
| 0x78 | W | CRTC `SUR`(スムーススクロール上) |
| 0x7A | W | CRTC `SDR`(スムーススクロール下) |
| 0x7C | R/W | **GRCG モードレジスタ**。bit7:6 = GRCG 動作モード、bit5:4 = GDC との併用(GRCG チップ 2 以上) |
| 0x7E | **W のみ** | **GRCG タイルレジスタ**。書くたびに 4 段のカウンタが進む(0x7C 書き込みでリセット) |
| 0x70-0x7A | R | **未接続 → 0xFF** |
| 0x7E | R | 未接続 → 0xFF |

- レジスタ番号は `(port & 0x0E) >> 1` = A3:A1。
- **0x7C は読み戻せる**(`grcg.modereg` をそのまま返す)。
- GRCG が搭載されていない構成(`grcg.chip == 0`)では 0x7C 書き込みが無視される。
- **リセット値**: `crtc_reset()` で全ゼロ、`grcg.modereg = 0`、タイル 0。

### 9.3 グラフィック GDC(スレーブ)+ パレット

`iocore_attachsys{out,inp}ex(0x00A0, 0x0CF1, tbl, 8)`。A0=0 固定、エイリアス無し。

| ポート | R/W | レジスタ |
|---|---|---|
| 0xA0 | W | **スレーブ GDC パラメータ** |
| 0xA0 | R | スレーブ GDC ステータス(§9.1 と同じビット定義) |
| 0xA2 | W | **スレーブ GDC コマンド** |
| 0xA2 | R | スレーブ GDC リードデータ(無ければ 0xFF) |
| 0xA4 | R/W | **表示 VRAM バンク選択**(bit0)。読み戻し可 |
| 0xA6 | R/W | **アクセス VRAM バンク選択**(bit0)。読み戻し可 |
| 0xA8 | W | パレット: 16 色/256 色モードならパレット番号、デジタル 8 色モードなら G 成分パック |
| 0xAA | W | 16 色モードなら G 値、デジタルなら B 成分パック |
| 0xAC | W | 16 色モードなら R 値、デジタルなら R 成分パック |
| 0xAE | W | 16 色モードなら B 値、デジタルなら G 成分パック |
| 0xA8-0xAE | R | **PC-9821 ビルドのみ読み出し可**。9801 ビルドでは未接続 → 0xFF |

**モードによってレジスタの意味が変わる**のが厄介な点:
デジタル 8 色モードでは 0xA8/0xAA/0xAC/0xAE が 4 ビットずつのパックされた
プレーン別パレット、アナログ 16 色モードでは 0xA8 がインデックス、0xAA/AC/AE が G/R/B。
256 色モード(9821)ではさらに別。

### 9.4 CG-ROM(漢字/フォント)

`io/cgrom.c`。`iocore_attachsys{out,inp}ex(0x00A1, 0x0CF1, tbl, 8)`。
**A0=1 固定**なので、偶数側のグラフィック GDC と交互に並ぶ。

| ポート | R/W | レジスタ |
|---|---|---|
| 0xA1 | W | **文字コード上位バイト** |
| 0xA3 | W | **文字コード下位バイト** |
| 0xA5 | W | **ラスタ行**(bit4:0 = 行、bit5 = 左右(L/R)半角選択の反転) |
| 0xA7 | — | 未接続 |
| 0xA9 | R/W | **フォントパターン**。読み = 現在の code/line のパターン、書き = ユーザ定義文字への書き込み(code の下位が 0x56 の範囲のみ) |
| 0xAB,0xAD,0xAF | — | 未接続 |
| 0xA1,0xA3,0xA5 | R | 未接続 → 0xFF |

CG ウィンドウ(0xA4000-0xA4FFF)の位置は 0xA1/0xA3/0xA5 の書き込みで決まる。
詳細は `docs/PC98_MACHINE_SPEC.md` の該当章。

### 9.5 EGC

`io/egc.c`。`iocore_attachout(0x04A0 + i, ...)` を 16 本(16bit デコード、**W のみ**)。

| ポート | レジスタ |
|---|---|
| 0x04A0/0x04A1 | アクセスプレーン(16bit) |
| 0x04A2/0x04A3 | FG/BG 制御 |
| 0x04A4/0x04A5 | オペレーション |
| 0x04A6/0x04A7 | 前景色 |
| 0x04A8/0x04A9 | マスク(FG/BG 制御の bit14:13 が 0 のときのみ書ける) |
| 0x04AA/0x04AB | 背景色 |
| 0x04AC-0x04AF | シフト/ビット長 |

- **`mode2` の EGC ビットが立っていないと書き込みは丸ごと無視される。**
- 16 ビット幅アクセスの専用パス(`egc_w16`/`egc_r16`)がある。
  レジスタ選択は `port & 0x0F`。
- **読み出しは `iocore_attachinp` されていない → 0xFF**。ただし
  `iocore_inp16` は 0x04A0-0x04AF を `egc_r16` に流す(`(port & 0xFFF1) == 0x04A0` の判定)。
  **8 ビット IN と 16 ビット IN で挙動が違う**という NP2 の不整合。

## 10. CPU / メモリ / システム制御

### 10.1 CPU 制御 0xF0-0xF6

`io/cpuio.c`。`iocore_attachsys{out,inp}ex(0x00F0, 0x0CF1, tbl, 8)`。A0=0 固定。

| ポート | R/W | 機能 |
|---|---|---|
| 0xF0 | W | **CPU リセット要求**。A20 を落とし `CPU_RESETREQ` を立てる。80286 のプロテクトモード脱出に使う。データ値は無関係 |
| 0xF0 | R | 通常 **0x00**。AMD-98 サウンド有効時のみ 0x18 |
| 0xF2 | W | **A20 ゲート ON**。データ値は無関係 |
| 0xF2 | R | A20 が有効なら **0xFE**、無効なら **0xFF** |
| 0xF4 | — | 未接続 |
| 0xF6 | W | IA-32 ビルドのみ。値 0x02 = A20 ON、0x03 = A20 OFF |
| 0xF6 | R | IA-32 ビルドのみ。bit0 = A20 マスク中、bit1 = NMI 許可中 |
| 0xF8-0xFE | — | 未接続 |

> 0xF0 / 0xF2 は 16 ビット IN では `TERM_WORD` 扱いで **0x2588** が返る(§1.2)。

### 10.2 NMI マスク

`io/nmiio.c`。`iocore_attachsysoutex(0x0050, 0x0CF1, tbl, 2)`(**W のみ**)。
自由ビットは A3,A2,A1 で `nfuncs=2` → **A2,A3 が don't care**。

| ポート | R/W | 機能 |
|---|---|---|
| 0x50 | W | **NMI 禁止**。データ値は無関係 |
| 0x52 | W | **NMI 許可**。データ値は無関係 |
| 0x54,0x58 | W | 0x50 のエイリアス |
| 0x56,0x5A | W | 0x52 のエイリアス |
| 0x5C,0x5E | W | 本来 0x50/0x52 のエイリアスだが、**ARTIC(§10.3)が後から 0x5F を上書きする**。0x5C/0x5E の OUT はエイリアスのまま残る |
| 0x50-0x5E | R | 未接続 → 0xFF |

- **リセット値**: `nmiio_reset()` で `enable = 0` = **NMI 禁止**。
- エイリアスは NP2 の `nfuncs=2` 指定の副作用。実機が 0x54-0x5A をデコードするかは
  このソースからは判断できない。**再実装では 0x50/0x52 だけをデコードするのが安全。**

### 10.3 ARTIC(フリーランカウンタ)

`io/artic.c`。16bit デコード。

| ポート | R/W | 機能 |
|---|---|---|
| 0x5C | R | カウンタ bit7:0 |
| 0x5D | R | カウンタ bit15:8 |
| 0x5E | R | カウンタ bit15:8(0x5D と同じ) |
| 0x5F | R | カウンタ bit23:16 |
| 0x5F | W | 何もしないが **CPU クロックを 20 消費する**(ウェイト挿入の模擬) |

16 ビット IN では `artic_r16` が使われ、`port & 2` で 8 ビットシフトする。
カウント周期は CPU クロック /(multiple × 13 または 16)。

### 10.4 ROM バンク切替 0x043D ほか

`io/necio.c`(NEC 機)/ `io/epsonio.c`(EPSON 互換機)。すべて 16bit デコード。

| ポート | R/W | 機能 |
|---|---|---|
| 0x0439 | **W のみ** | NP2 は値を保持するだけ(`necio.port0439`)。**リセット値 0xFF**。実機ではメモリウィンドウ/シャドウ制御だが NP2 は未実装 |
| 0x043B | R/W | **bit2 のみ**保持・読み戻し。他ビットは 0 で返る。EPSON 機では未接続 |
| **0x043D** | **W のみ** | **ITF ROM バンク切替**。書き込み値で分岐: **0x10 = ITF バンク ON**、**0x12 = ITF バンク OFF**。それ以外の値は無視 |
| 0x043F | W | EPSON 機のみ。0x42 = バンク I/O 許可、0x40 = 禁止 |
| 0x0C07 | W | EPSON 機のみ。ROM イメージのコピーモード |
| 0x0C03 | R | EPSON 機のみ。CPU モード文字('R' か 'P') |
| 0x0C13 / 0x0C14 | R | EPSON 機のみ。常に 0x00 |
| 0x043D | R | **未接続 → 0xFF**。読み戻しはできない |

**0x043D の意味**(`mem/memepp.c` の `memf800_rd8`):
`CPU_ITFBANK` が 1 のとき、**0xF8000-0xFFFFF の読み出しが `VRAM_STEP` だけずれた
別の ROM 領域(ITF ROM)に向く**。0 なら通常の BIOS ROM。

- **電源投入時は ITF バンクが有効**(ITF ROM から起動して、初期化を終えたら
  0x043D に 0x12 を書いて通常 BIOS に切り替える)というのが PC-98 の起動フロー。
  NP2 の `CPU_ITFBANK` の初期値は CPU コアの初期化に依存しており、
  `necio_reset()` はこれを触らない。**再実装ではリセット時に ITF 側を選ぶこと。**
- EPSON 機では 0x043D に 0x00/0x02 も来る(0x043F で許可されている場合のみ有効)。

### 10.5 EMS(拡張メモリバンク)

`io/emsio.c`。16bit デコード。`emsio.maxmem`(= 拡張メモリ量)が 0 でないときのみ登録。

| ポート | R/W | 機能 |
|---|---|---|
| 0x08E1 | W | バンク 0(0xC0000-0xC3FFF)のページ |
| 0x08E3 | W | バンク 1(0xC4000-)のページ |
| 0x08E5 | W | バンク 2(0xC8000-)のページ |
| 0x08E7 | W | バンク 3(0xCC000-)のページ |
| 0x08E9 | R/W | **バンクターゲット(メガバイト単位のセグメント選択、bit3:0)** |

- 0x08E9 の読み出し: ターゲットが 1 以上かつ実装メモリ量以内なら **0x00**、
  それ以外(0 または範囲外)なら **0xFF**。**これが EMS の存在検出に使われる。**
- 0x08E1-0x08E7 の書き込みは、ターゲットが 0 のときは物理アドレスを既定に戻し、
  そうでなければ `(target << 20) + ((dat & 0xFC) << 12)` を割り当てる。

### 10.6 DIP スイッチ読み書き 0x8x1E

ハンドラ登録ではなく `defout8`/`definp8` のフォールバックで処理される
(`(port & 0xF0FF) == 0x801E` の判定)。つまり **A15:A12 = 1000、A7:A0 = 0x1E、
A11:A8 は don't care**。

| ポート | R/W | 内容 | 既定値 |
|---|---|---|---|
| 0x841E | R/W | **DIP SW 1**(bit7:2 のみ)。bit0 は読み出し時に内部フラグで埋まる | `dipsw[0] = 0x3E` |
| 0x851E | R/W | **DIP SW 2**(bit7:5,3:0)。bit4 は 0x871E 経由 | `dipsw[1] = 0xE3` |
| 0x861E | R/W | **DIP SW 3**(bit6:0) | `dipsw[2] = 0x7B` |
| 0x871E | R/W | DIP SW 2 の bit4 + BEEP 音量(bit3:2) | — |
| 0x8E1E | R/W | DIP SW 3 の bit7 | — |

**DIP スイッチのうち I/O 応答に直接効くもの**:

| ビット | 影響 |
|---|---|
| `dipsw[0]` bit0 (SW1-1) | 0x33 の bit3、GDC の初期 mode1(0x98/0x80)と 15kHz/24kHz |
| `dipsw[0]` bit2 (SW1-3) | 0x42 の bit4、GDC のプラズマ表示フラグ |
| `dipsw[0]` bit3 (SW1-4) | **0x94/0xCC の bit2 か bit3**(1 → bit2=内蔵優先、0 → bit3=外付け優先) |
| `dipsw[0]` bit7 (SW1-8) | 0x42 の bit3 |
| `dipsw[1]` 全体 | **0x31 の読み出し値そのもの** |
| `dipsw[2]` bit7 | 0x42 の bit1(EPSON 機)、メモリ構成 |

## 11. その他の本体側ポート

### 11.1 RS-232C(8251)

`io/serial.c`。`iocore_attachsys{out,inp}ex(0x0030, 0x0CF1, tbl, 2)`。
A0=0 固定、`nfuncs=2` → **A2,A3 が don't care(0x34-0x3E にエイリアス)**。

| ポート | R/W | レジスタ |
|---|---|---|
| 0x30 | R/W | **データレジスタ** |
| 0x32 | W | **モード/コマンドレジスタ**(8251 の 2 段書き込み) |
| 0x32 | R | **ステータス**。bit0=TxRDY, bit1=RxRDY, bit2=TxEMP, bit5:3=エラー(パリティ/オーバーラン/フレーミング), bit7=**DSR 非アクティブのとき 1** |
| 0x34-0x3E(偶数) | R/W | エイリアス |
| 0x0130-0x013A | R/W | `SUPPORT_RS232C_FIFO` ビルドのみ。FIFO 拡張レジスタ群 |

**リセット値**: `rs232c.result = 0x05`(TxRDY|TxEMP)、`data = 0xFF`、
`cmd = 0x27`(送受信許可)。ボーレートは 8253 ch2 が決める。

**シリアルポートが繋がっていない機械**では `rs232c_stat()` が 0 を返すので、
**0x32 の読み出しは 0x85**(= 0x05 | 0x80)、
**0x33(8255 ポート B)の bit7:5 は 0** になる。既定 DIP では 0x33 = **0x08**。

### 11.2 プリンタインタフェース(8255)

`io/printif.c`。`iocore_attachsys{out,inp}ex(0x0040, 0x0CF1, tbl, 4)`。
A0=0 固定、`nfuncs=4` → **A3 が don't care(0x48-0x4E にエイリアス)**。

| ポート | R/W | レジスタ |
|---|---|---|
| 0x40 | W | **プリンタデータ(ポート A)** |
| 0x42 | R | **ステータス + マシン識別(ポート B)** — 下表 |
| 0x44 | — | **未接続**(実機ではポート C = ストローブ等) |
| 0x46 | — | **未接続**(実機ではコントロールワード) |

**0x42 read のビット**:

| bit | 値 |
|---|---|
| 7 | **常に 1** |
| 6 | **常に 0**(プリンタ BUSY を NP2 は模擬しない) |
| 5 | 1 = 8MHz 系 CPU クロック、0 = 5/10MHz 系 |
| 4 | DIPSW1-3 |
| 3 | DIPSW1-8 |
| 2 | **常に 1** |
| 1 | 1 = V30、0 = 80286 以降(EPSON 機では DIPSW3-8) |
| 0 | **常に 0** |

**既定 DIP スイッチでの返り値は 0x94**(0x84 | 0x10)。V30 コアなら 0x96。
このポートは機種判別に使われるので値が効く。

### 11.3 カレンダ時計 µPD4990

`io/upd4990.c`。

| ポート | R/W | 機能 | 登録 |
|---|---|---|---|
| 0x20 | W | **µPD4990 シリアル制御**。bit3=STB、bit4=CLK、bit2:0=コマンド、bit5=データ | `sys`, mask 0x0CF1, nfuncs=1 → **0x20,0x22,...,0x2E すべてに張られる** |
| 0x0022 | R/W | `SUPPORT_HRTIMER` ビルドのみ。**中身は 1 バイトのスクラッチ**(書いた値がそのまま読める)で時計とは無関係。16bit デコードなので 0x20 のエイリアスを上書きする | `ext` |
| 0x0128 | R/W | `SUPPORT_HRTIMER` ビルドのみ。**高分解能タイマの分周設定**。W: bit1:0 = 0/1/2/3 → 分周 64/32/停止/16。R: 0x80/0x81/0x82/0x83 を返し、同時に **IRQ15 をクリアする** | `ext` |

**時計データの読み出し**は 0x33(8255 ポート B)の bit0 経由。
`iocore_attachsysoutex(0x0020, 0x0CF1, updo20, 1)` は nfuncs=1 なので、
**0x20,0x22,0x24,...,0x2E の全部が同じハンドラに張られる**。ただし
0x21-0x2F の奇数は DMA バンクなので衝突しない(偶数/奇数で分離)。
0x20 の **IN は未接続 → 0xFF**。

### 11.4 マウス(第 2 の 8255)

`io/mouseif.c`。16bit デコード。

| ポート | R/W | レジスタ |
|---|---|---|
| 0x7FD9 | R/W | **ポート A**。読み = X/Y カウンタのニブル + ボタン(bit7:4) |
| 0x7FDB | R/W | ポート B。読みは常に 0x40(モード設定時) |
| 0x7FDD | R/W | **ポート C**。bit7 = カウンタラッチ、bit6 = X/Y 選択、bit5 = 上位/下位ニブル選択、bit4 = 割り込みタイミング |
| 0x7FDF | W | **コントロールワード**。bit7=1 でモード設定、それ以外はポート C のビットセット/リセット |
| 0xBFDB | W | 割り込み周期の設定(bit1:0) |
| 0x7FDF | R | 未接続 → 0xFF |

**リセット値**: portA=0x00, portB=0x00, **portC=0xF0**, mode=0x93。

ポート C の読み出しは 8255 のモードによってマスクが変わり、
下位ニブル入力モードのときは **bit3=1 固定 + DIPSW3 の bit7 + DIPSW1 の bit5:4 の反転**が
埋め込まれる。

### 11.5 320KB FDD インタフェース(スタブ)

|---|---|---|
| 0x51 | R | **常に 0x00** |
| 0x53 | — | 未接続 |
| 0x55 | R | 読むたびに **0x00 と 0xFF がトグルする**(「動いている」ふりをするだけ) |

## 12. NP2kai が近似・省略している箇所(正直な穴)

再実装で「NP2 に合わせても実機に合っているとは限らない」場所。

1. **8237 のコマンドレジスタ(0x11 write)が未実装。**
   `dmaco00[8]` が NULL で、書き込みは捨てられる。コントローラのイネーブル、
   メモリ間転送、優先度回転、DREQ/DACK の極性がどれも設定できない。
   NP2 は「常に有効・固定優先度」で動いている。

2. **8237 のモードレジスタ(0x17)は bit5(アドレス増減)しか見ていない。**
   転送タイプ(読み/書き/検証)、シングル/ブロック/デマンド、オートイニシャライズは
   すべて無視され、実際の転送は各デバイスの `dmaproc` が駆動する。

3. **0x29(DMA バウンダリ)の意味が確定できない。**
   `bound` を保存して `bound != 3` かどうかでアドレス合成を変える、という
   コードにコメントが無く、`lastaddr` の計算には明らかにバグ(バンクの二重 OR)がある。
   実機仕様の裏取りが必要。

4. **8253 の分周そのものはエミュレートされていない。**
   カウンタ値は CPU クロック換算のイベント時刻に変換され、読み出し時に逆算される。
   入力クロック(2.4576MHz / 1.9968MHz)の切り替えは
   `pccore.cpumode & CPUMODE_8MHZ` を通じて BEEP の初期値にだけ現れる。
   PIT を実クロックで作る FPGA 実装のほうが正確になる。

5. **0x94 read が完全な定数**。DMA イネーブル状態も実際のドライブ READY も
   反映しない。0x90 系では bit5/bit4 が常に 0、0xCC 系では常に 1、という
   ハードコードで、根拠がコードから読めない。ここは実機ドキュメントで
   確認する価値がある。

6. **FDC のリセット(0x94 bit7)後の割り込み挙動が怪しい。**
   bit7 の 0→1 かつ bit3=1 のときだけ 4 台分の遅延割り込みを仕込むが、
   仕込む ST0 は現在の `fdc.stat[i]`(通常 0)なので、SENSE INTERRUPT STATUS は
   結局 0x80(no pending)を返す。コード中のコメントは OSASK 向けの
   ワークアラウンドだと明言している。**実機では 4 回の AI(0xC0|unit)が返るはず。**

7. **`sys` デコードが A9:A8 を見ない**(PC-9801 ビルド)。§1 のとおり。
   PC-9821 ビルドの `sysiomsk=0xFF00` 経路がフルデコードで、そちらが正しい。

8. **`cmn` デコード(FDC 0x90 系、320KB I/F)が上位バイトを完全に無視する。**
   0x0190、0x0290… でも FDC に当たる。実機はさすがにデコードしているはずで、
   これは NP2 の割り切り。

9. **エイリアス(A2/A3 の don't care)が実機に存在するかは不明。**
   PIC の 0x04/0x06、PIT の 0x79-0x7F、8255 の 0x39-0x3F、
   キーボードの 0x45-0x4F、NMI の 0x54-0x5A。
   NP2 の `nfuncs` 指定の副作用として生じているだけで、
   これを実機仕様だと読むべきではない。**再実装は狭くデコードしておき、
   動かないソフトが出たら広げる**のが安全。

10. **EGC が 8 ビット IN に応答しない**(0xFF)のに 16 ビット IN には応答する。
    NP2 内部の不整合。実機は両方応答するはず。

11. **8255(0x37)と第 2 の 8255(0x7FDF)でモードワードの扱いが違う。**
    システムポート側は mode word を完全に無視し、マウス側は保存して
    ポートの読み出しマスクに使う。実機は両方とも本物の 8255。

12. **プリンタ 8255 のポート C / コントロールワード(0x44/0x46)が未実装。**

13. **`0x0439` が何もしていない。** 値を保持するだけ。実機では
    メモリウィンドウ/シャドウ RAM 制御に関わる。ITF が使うなら要調査。

14. **DMA の `TERM_WORD` 扱い**(16bit OUT で下位バイトすら書かない)は
    NP2 独自の解釈に見える。実バスなら下位バイトは書かれるはず。

## 13. 「起動させるために最低限これを返す」チェックリスト

FPGA 側が空実装のときに、少なくともこの値を返しておけば
初期化ループで止まらない、というまとめ。

| ポート | R/W | 返すべき値 | 理由 |
|---|---|---|---|
| 0x00BE | R | **0xFB**(= 0xF8 \| chgreg[1:0]、リセット時 chgreg=3) | I/F 検出。bit3=1 は必須 |
| 0x00BE | W | bit1:0 をラッチし、bit0 で 0x9x/0xCx の応答を切り替える | これを無視すると両系統が応答して破綻 |
| 0x0090 | R | **アイドル時 0x80**(RQM のみ)。結果フェーズは 0xD0 \| (1<<unit) | RQM 待ちループを抜ける |
| 0x0092 | R/W | RQM/DIO の条件を満たすときのみ実データ。それ以外は直前値 | コマンド/リザルトの整合 |
| 0x0094 | R | **0x44**(`dipsw[0]` bit3 = 1 の既定時) | bit6=1 が必須 |
| 0x0094 | W | bit7 立ち上がりで FDC をリセットし 0x90 を 0x80 に戻す | リセットシーケンス |
| 0x00C8/0xCA/0xCC | R | 0xBE bit0 = 1 の間は **0xFF** | 未選択系統は黙る |
| 0x0043 | R | **0x85**(キー無しアイドル) | 8251 TxRDY/TxEMP/DSR |
| 0x0031 | R | DIP SW 2 の値(既定 **0xE3**) | 機種構成の判定 |
| 0x0033 | R | bit3 = DIPSW1-1 の反転、他は 0 でよい | |
| 0x0035 | R | 書いた値の読み戻し(リセット値 **0xF9**) | ビットセット/リセットの整合 |
| 0x0042 | R | **0x94**(既定 DIP、80286 以降) | 機種識別 |
| 0x0060 / 0x00A0 | R | **bit7 = 1** を必ず立てる。bit5 に VSYNC、bit2 に FIFO 空 | GDC 待ちループ |
| 0x0011 | R | DMA ステータス(TC フラグ)。読んだら下位ニブルをクリア | |
| 0x0071-0x0077 | R/W | 8253 のカウンタ読み書きが往復すること | メモリ/クロック計測 |
| 0x00F2 | R | A20 有効なら **0xFE** | |
| 0x043D | W | **0x10 で ITF ROM、0x12 で通常 BIOS** に切り替える | 起動フローの本体 |
| 未実装ポート | R | **0xFF** | NP2 の既定と揃える |
