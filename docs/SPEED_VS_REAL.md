# コア速度 対 実機 — すべての「遅い所」「速すぎる所」を隠さないための比較表

作成: 2026-11-14 / 対象: `combo4-dbg-s29`（HEAD `08bc561`、firmware は d161c81 の GDC 改良込み）
再生成: `scripts/speed_vs_real.sh`（全体 約 4 分）/ `scripts/speed_vs_real.sh --quick`（約 2 分）

§1〜§6 は `08bc561` 時点の計測（RTL もファームウェアも変えずに測った値）。そのあと
`fw-latency` ブランチで 0 ALM の修正 5 件（GDC_LINGER、タイマ IRQ、サービス間の譲り合い、
rhythm.bin 再試行、FDD シークの `clock_rate`）を入れ、同じベンチで測り直した。
**修正前後の対照は §7**。§0 と §4 の表は修正後の値（括弧内が修正前）に更新してある。
比はすべて **比 = コアの時間 / 実機の時間** で、1 より大きければコアが遅い。

- **> 1.2** は「遅い（要注意）」、**< 0.8** は「速すぎる（要注意）」として **太字** で示す。
- 基準機は PC-9801 UX/VX クラスの 286 で、既定は **10 MHz（2.4576 MHz 系、CPU 9.8304 MHz）**。
  8 / 12 MHz / Turbo の列は差がある行にだけ書く。
- 「測定」= この文書のベンチで実測した値。「推定」= 資料・np21w の式・コード読みから計算した値。
  「未測定」= どちらの根拠も弱く、数字を出していないもの。

凡例（推奨実装 列）:

| 値 | 意味 |
|---|---|
| **回路必須** | ゲストが頻繁にビジーウェイトする。遅れがそのまま処理落ち・カクつきになる |
| **FWで可（速度改善）** | FW のままでよいが速度改善が必要。ゲストは待つが頻度は低い |
| **FWで可** | FW のままでよい。ゲストは待つが、実機もそこは遅い（実機の 2HD より遅くなければ可） |
| **FW向き** | ゲストは待たない。起動時かユーザ操作時だけ（OSD・設定・イメージのヘッダ解析） |

「計時」列の **⚠** は、平均が合っていても**時間の形**（ばらつき、回転待ちの有無、処理の長さの比率）を
計時ソフト（コピープロテクト、速度判定、GDC クロック判定）が見分けうる行。

### 2.2 GDC 描画（ファームウェア）

`sim/tb_speed_fw.sv`: 実 `softcpu_subsystem`（picorv32 + 出荷 `firmware.vh`）を clk_chipset 42.954545 MHz で動かし、
`pc98_gdc` のスナップショット / done ハンドシェイクと svc チャネルをモデル化（svc 応答 6 pico クロック）。
時間は **要求（DRAWING 立上り）→ retire（DRAWING 立下り）**。
実機基準は np21w `io/gdc_sub.c` `calc_gdcslavewait`: **1 ドット 0.720 µs + 1 コマンド 12.2 µs**
（`dots × 27648 / 15625` ベースクロック + 30 ベースクロック。8 MHz 系も 1 ドットは同じ 0.720 µs、固定分は 15.0 µs）。
GDC は CPU クロックと無関係なので 8/12 MHz/Turbo でも比は同じ（ゲスト CPU の速さはこの行に効かない）。

### 2.3 FDD（RTL の floppy.v + ファームウェアのセクタ移送 + APF）

コアの 1 セクタ = **ファームウェアが FIFO を満たす時間**（測定、`tb_speed_fw`）+ floppy.v の固定待ち
`command_wait_counter` 4000 clk = **93 µs**（FDD Turbo 時 500 clk = 11.6 µs、コード読み）+ DMA の吸い出し（未測定）。
ファームウェアは 1 バイトずつ `FDD_MGMT_PUSH` に書くので **1024 バイトで約 8.5 ms（1 バイト約 8.3 µs）**。

実機基準（計算）: 2HD は 360 rpm・500 kbps・8 セクタ×1024 B/トラック。1 回転 166.7 ms、
連続読み 1 セクタ枠 **20.8 ms**（うちデータ 16.4 ms）、ランダムは平均回転待ち 83.3 ms + シーク。
np21w `io/fdc.c` は結果割り込みを 512 CPU クロック後（10 MHz で 52 µs）に出し、DMA は一括（瞬時）。

### 2.4 SCSI HDD（RTL の窓 + ファームウェアのコマンド実行 + APF）

### 3.1 実機と時間の形が違って見えうるステータス

- **GDC DRAWING（status bit3）**: 立上りは実機どおり即時だが、立下りまでが 60〜150 倍長い。さらに主ループの状況で
  ±数十 ms ゆれる。描画時間を測る GDC クロック判定（2.5 / 5 MHz）や、DRAWING を回数で待つループは別物に見える。⚠
- **GDC FIFO EMPTY（bit2）**: 描画中は 0 に保たれる（スロットル）。np21w は 1 のまま。EMPTY を待ってからコマンドを
  書くドライバは描画完了まで止まる（結果は正しいが待ちが長い）。
- **FDC**: シーク終了 IRQ（SENSE INTERRUPT までの間隔）は RTL の (16−SRT) ms/ステップで実機どおり（12 MHz / Turbo 設定時は
  1/2・1/4 に縮む。§2.3）。READ DATA の結果 IRQ はセクタ移送（ファームウェア 8.8 ms）+ 93 µs 後で、**回転位相に無関係**。
  サービス間干渉で最大 78 ms 遅れる。⚠
- **SCSI**: フェーズ遷移は RTL、コマンド実行はファームウェア。受付が 55 µs〜78 ms と大きくゆれ、データ量に比例して
  1 ブロック 4.4 ms ずつ伸びる。シーク時間はない。⚠
- **OPNA BUSY**: jt12 の固定 24 µs で、レジスタ種別による長短（2.1〜72 µs、SSG は 0）がない。⚠

## 5. 次に回路へ移すものの優先順位

ALM はすべて**推定**（まだ `scripts/measure_core.sh` で測っていない）。現状の空きは `docs/PC98_GDC_DESIGN.md` の時点で約 1,480 ALM。

1. **GDC 描画エンジン（VECTL / VECTR / VECTT / TEXTE / WDAT と単点）を RTL に** — 推定 **900〜1,500 ALM**。
   比 125〜138 → 1 前後。DRAWING の形も実機に近づき、サービス間干渉の最大要因（78 ms）が消える。
   VECTC（円弧）は np21w の表（4097×16 bit = M10K 7 個程度）と乗算器 1 個が要るので、後回しにして FW に残してもよい（+約 300 ALM + DSP 1）。
2. **ブリッジ RAM → FDD FIFO / SCSI バッファの転送回路** — 推定 **150〜300 ALM**。
   FW の 1 バイト 8 µs のストアが消え、FDD 1 セクタ 8.5 ms → APF 律速（≪1 ms）、SCSI 1 ブロック 4.4 ms → APF 律速。
   同時に GDC が SCSI / FDD に待たされる時間（70 ms / 9 ms）もほぼ消える。
3. **ファームウェアだけで直せるもの（0 ALM）** — **済**（`fw-latency`、§7）:
   `GDC_LINGER` を時間で区切る（13 ms → 数百 µs）、OSD を閉じているときの IRQ を軽くする（CPU 30% の回収）、
   `rhythm_load` の再試行を間引く、`gdc_poll` を 1 図形ごとに主ループへ返す（SCSI/FDD の 78 ms 待ちを分割）。
4. **floppy.v の `clock_rate` を CPU 速度設定から切り離す** — **済**（`fw-latency`、§7）。推定 **≈0 ALM**（配線の変更）。
   12 MHz / Turbo 設定でシークが 2 倍・4 倍速になるのを直す（FDD Turbo とは独立に）。
5. **OPNA の BUSY をレジスタ種別ごとに**（17 / 47 / 83 / 576 φM、SSG と ADPCM は 0） — 推定 **40〜80 ALM**。OPNA を載せる構成でのみ。
6. **FDD の回転位相モデル**（インデックス周期 166.7 ms、セクタ位置に応じた待ち）— 推定 **100〜200 ALM**。
   コピープロテクト対策。全体を遅くするので OSD で切り替え可能にする。

## 6. 測定方法と再生成

- `scripts/speed_vs_real.sh` が次を走らせ、`.simout/speed_vs_real/report.txt` に比を並べる。
  `--timing` ベンチなので AGENTS.md に従い `pc98-sim` の docker イメージで動かす（`NO_DOCKER=1` でホストの verilator）。
  1. `scripts/sim_cycle_table.sh 0 1 2 3`（`--quick` は 10 MHz のみ）
  2. `sim/tb_speed_fw.sv` を 3 通り: APF 1 µs/転送（`+tdslat=43`）、APF 1 ms/転送（`+tdslat=43000`）、svc 30 pico クロック（`+svclat=30 +quick`）。
     `--quick` は GDC の行だけ。
- `tb_speed_fw` の前提（数字に**含まれていない**もの）:
  - APF の本当の往復時間（ARM + SD）。行ごとに転送回数 `tds=` を出しているので、実機の APF 遅延 × 回数を足して読む。
    実機の APF 遅延は**未測定**で、1 µs と 1 ms の 2 点で幅を示した。
  - `pc98_gdc` / `floppy.v` / `pc98_scsi` は要求線・FIFO・CDB のレジスタモデル。RTL 側の時間（floppy.v の 93 µs、DMA など）は入っていない。
  - svc チャネルの応答は 6 pico クロック固定（ゲストが VRAM を叩いている間の待ちは入っていない）。
  - D88 経路: ベンチでは D88 判定が通らなかった（同じ配置の画像を `sim/host/fdd_fw_host.cpp` は D88 としてマウントする。
    ベンチのブリッジ RAM の扱いに原因があると見ているが未解決）。そのため D88 の冷えたトラックの行は転送回数からの推定。
- 実機基準の出典:
  - CPU / VRAM / I/O: 80286 データシート + np21w `pccore.c`（VRAM ウェイト）+ `io/iocore.c`（busclock）。`scripts/sim_cycle_table.sh` 内の表。
  - GDC: np21w `io/gdc_sub.c` `calc_gdcslavewait`。
  - FDD: 2HD の規格（360 rpm、500 kbps、8×1024 B）からの計算。np21w `io/fdc.c` `fdc_intwait`（512 クロック）。
  - SCSI: np21w `cbus/scsiio.c`（4000 クロック）。実機の -55 + ドライブは一般的な当時の値からの**推定**。
  - OPNA: `docs/ref/pc98-timing-conventions.md` §2 の YM2608 BUSY 表と `jt12_mmr.v`。

注:
- FDD のセクタは**実機の 2HD（20.8 ms）よりさらに速く**なった（0.42 → 0.36）。回転待ちが無いことは変わらない（§2.3、§5 の 6）。
- 譲り合いの入れ子でスタックの最深は 416 → 約 656 バイト（main 384 + IRQ 272、`-fstack-usage` をコールグラフで合計）。
  .data + .bss は 1149 バイトなので 2 KB の RAM に約 240 バイト残る（`firmware/system.ld` のコメント）。
  リリース構成（.bss 1080）では約 110 バイトなので、さらに深い入れ子や大きなフレームを足すときは測り直す。
- 譲り合いの点では、そのサービスの途中状態（FDD_MGMT_ADDR、FDD_BRAM_ADDR、ブリッジ RAM 0〜127 語、
  ターゲットデータスロット）が他に壊されないことを確認してある: SCSI はブロックの区切り、FDD は
  ステージが 256 語以上（SCSI が触らない領域）のときだけ譲り、譲ったあと 2 つのポインタを張り直す。
